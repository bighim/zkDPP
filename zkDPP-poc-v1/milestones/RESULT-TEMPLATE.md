# Milestone Result Template

Result는 완료된 milestone을 독립적으로 기억하고, 실제 구현·검증·성능을 확인하는 문서입니다. 구현 전 명세를 읽지 않아도 큰 그림이 보여야 합니다.

## Metadata

```markdown
- 상태: 완료 | 부분 완료 | 실패
- 구현 명세: [링크]
- Raw 결과: [링크]
- 실행 횟수: Setup N회, 측정 N회
```

## 0. 30초 안에 기억 복구하기

첫 50줄 안에 다음 표를 둡니다.

| 질문 | 답 |
|---|---|
| 이전 상태 | 이전 milestone에서 가능했던 것 |
| 이번 목표 | 해결하려던 문제 |
| 실제 구현 | 새로 추가한 기능 |
| 이제 가능한 것 | 실제 실행 가능한 흐름 |
| 검증 | 대표 correctness 결과 |
| 대표 성능 | 핵심 constraints·gas·E2E |
| 미포함 | 아직 없는 기능 |
| 다음 단계 | 다음 milestone |

대표값만 표시하고 전체 breakdown은 뒤로 보냅니다.

## 1. 이전 milestone에서 무엇이 달라졌나요?

| 이전 | 이번에 추가 | 현재 가능 |
|---|---|---|

## 2. 실제로 어떤 동작을 구현했나요?

객체 전이와 핵심 흐름을 간단하게 보여줍니다. 상세 수도 코드는 구현 전 명세로 연결합니다.

Circuit과 Contract가 함께 등장하는 milestone은 다음 책임을 같은 절에서 구분합니다.

| 기능 | Circuit이 확인하는 것 | Contract가 확인·변경하는 것 |
|---|---|---|

검증 관계만 제공하는 Kernel과 실제 Ledger 상태를 변경하는 Event를 같은 기능처럼 표현하지 않습니다.

## 3. 무엇이 공개되고 무엇이 숨겨지나요?

| 기능 | 공개값 | 비공개값 |
|---|---|---|

## 4. 어떤 상태를 저장하나요?

| 상태 | 역할 | 변경 기능 |
|---|---|---|

저장 상태가 없는 milestone은 `해당 없음`이라고 명시합니다.

## 5. 계획과 실제 구현이 달랐나요?

| 항목 | 계획 | 실제 | 이유·영향 |
|---|---|---|---|

차이가 없으면 `Protocol 의미 변경 없음`이라고 기록합니다.

## 6. Correctness와 최종 상태

- 성공해야 하는 흐름
- 실패해야 하는 흐름
- Atomicity
- 일반 계산·Circuit·Contract 대조
- 최종 상태

실패 후 수정한 내용도 삭제하지 않고 기록합니다.

## 7. 무엇을 어디까지 측정했나요?

| 측정 | 포함 범위 | 제외 범위 | 단위·횟수 |
|---|---|---|---|

## 8. 실제 성능 결과

다른 단위를 한 표에 섞지 않습니다.

1. Circuit
2. Deployment·Setup
3. Event gas
4. Live E2E

각 표 바로 아래에 결과 해석을 붙입니다.

## 9. 어떻게 재현하나요?

실행 명령과 필요한 선행 artifact를 순서대로 기록합니다.

## 10. Artifact와 checksum

- Git에 포함하는 결과
- 재생성 가능한 결과
- Raw JSON과 checksum 위치

긴 Hash는 본문이 아니라 이 절이나 Raw JSON에 둡니다.

## 11. 무엇이 실패·제외·보류됐나요?

- 실패한 항목
- 의도적으로 제외한 기능
- Production으로 주장하지 않는 내용

## 12. 다음 milestone은 무엇을 이어받나요?

```text

  ...

  ...
```

## 작성 Gate

- Result만 읽어도 객체 전이·Privacy·상태 변화가 보입니다.
- 첫 50줄에서 8개 기억 복구 질문에 답합니다.
- 모든 성능값은 Raw JSON과 일치합니다.
- 미래형 요구사항 대신 실제 완료 결과를 과거형으로 씁니다.
- 명세의 상세 내용을 불필요하게 전부 복사하지 않습니다.
- 계획과 다른 점·실패·비범위를 숨기지 않습니다.
