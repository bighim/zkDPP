# Milestone 구현 전 Checklist

이 문서는 엄격한 목차 Template이 아닙니다. 구현 전에 필요한 결정이 빠지지 않았는지 확인하는 목록입니다. 해당 없는 항목은 `해당 없음`으로 기록합니다.

Milestone 명세 하나만으로 구현할 수 있어야 합니다. Architecture·Reuse·Future Context는 배경과 출처이며 명세의 필수 내용을 대신하지 않습니다.

## 문제와 목표

- [ ] 이전 milestone에서 이어받는 기능이 명확합니다.
- [ ] 이번 milestone이 해결할 문제를 한 문장으로 설명할 수 있습니다.
- [ ] 완료 후 새로 가능한 행동이 명확합니다.
- [ ] 중요한 대안과 선택 이유가 길다면 같은 폴더의 Background 문서에 보존되고 명세에서 연결됩니다.

## 범위

- [ ] 구현할 기능이 명확합니다.
- [ ] 구현하지 않을 기능이 명확합니다.
- [ ] 현재 기능·correctness·측정에 필요하지 않은 고도화를 넣지 않았습니다.

## 객체와 전이

- [ ] 역할과 신뢰 주체가 정해졌습니다.
- [ ] 객체와 State의 의미·단위·범위가 정해졌습니다.
- [ ] 입력·출력 객체 전이가 정해졌습니다.
- [ ] 생성·소비·terminal 조건이 정해졌습니다.

## Privacy와 검증 책임

- [ ] Public input이 정해졌습니다.
- [ ] Private witness가 정해졌습니다.
- [ ] Contract calldata로 공개되는 값이 정해졌습니다.
- [ ] 일반 계산·Circuit·Contract·외부 신뢰의 책임이 구분됩니다.
- [ ] 각 기능 절에 Native 관계와 전체 Circuit pseudo code가 함께 있습니다.
- [ ] Pseudo code는 한 줄 핵심과 번호가 있는 한글 단계 주석으로 흐름을 먼저 설명합니다.

## 상태와 Interface

- [ ] 저장할 상태와 각 상태의 역할이 정해졌습니다.
- [ ] 어떤 기능이 상태를 변경하는지 정해졌습니다.
- [ ] 주요 함수의 입력·출력·호출 권한이 정해졌습니다.
- [ ] 실패 시 원자성이 필요한 상태가 정해졌습니다.
- [ ] 함수별 상태 변화와 실패 조건이 해당 함수 설명 옆에 있습니다.

## 시나리오와 Gate

- [ ] 최소 Canonical 시나리오가 정해졌습니다.
- [ ] 반드시 성공해야 하는 경우가 정해졌습니다.
- [ ] 반드시 실패해야 하는 경우가 정해졌습니다.
- [ ] 일반 계산·Circuit·Contract 간 대조 방법이 정해졌습니다.

## 측정과 재사용

- [ ] 측정 대상·단위·시작·종료 경계가 정해졌습니다.
- [ ] 실행 횟수와 Raw 결과 위치가 정해졌습니다.
- [ ] 기존 기능의 재사용 범위와 새 구현 범위가 구분됩니다.
- [ ] Artifact·SRS·key lifecycle이 필요한 수준으로 정해졌습니다.
- [ ] 구현 폴더·명령·fixture 위치를 명세 하나에서 확인할 수 있습니다.

## 완료

- [ ] 완료 조건이 명확합니다.
- [ ] `RESULT-TEMPLATE.md`에 따른 Result 생성이 완료 조건에 포함됩니다.

## Colocation

- [ ] 목적·입력·출력·공개범위·pseudo code·상태 변화·실패 조건·측정이 기능별로 모여 있습니다.
- [ ] 실제 구현에 필요한 내용을 단순히 다른 문서 링크로 대체하지 않았습니다.
- [ ] 첫 화면 요약 이후에는 앞뒤 장을 반복해서 오가지 않고 기능 하나를 이해할 수 있습니다.
- [ ] 주석이 모든 코드 줄을 반복 설명하지 않고 3~8개의 논리 단계만 구분합니다.
- [ ] Background를 따로 두더라도 구현에 필요한 관계·공개범위·Interface·Gate는 명세에 반복됩니다.
