# ZKVeil: Privacy-Preserving Compliance Verification

## 3. 한 문장 요약과 전체 흐름

Buyer와 supplier의 identity·qualification, product specification, transaction amount를 공개하지 않고, trusted authority가 발급한 credential과 ZKP를 결합해 거래가 규제 policy를 만족하는지 확인한다.

## 4. 해결하려는 문제와 연구 목표

거래 data를 암호화하면 confidentiality는 얻지만 regulator가 compliance를 확인하려면 복호화가 필요하다. ZKVeil은 민감한 원문을 열지 않고도 predefined regulatory predicate를 검증하려 한다.

## 5. 저자가 주장하는 핵심 기여

- Supply-chain transaction을 위한 privacy-preserving compliance Scheme
- DID와 VC를 이용한 input authenticity 보강
- Identity, specification, amount predicate를 ZKP로 통합
- Security analysis와 100-node private-chain 평가

## 6. 시스템과 lifecycle 범위

Buyer와 supplier 사이의 transaction approval과 completion을 중심으로 한다. 제품 전체 lifecycle provenance보다 거래 단계 compliance가 핵심이다.

## 7. 등장 주체와 신뢰 가정

Buyer, supplier, blockchain network, identity authority와 qualification authority가 등장한다. Credential issuer가 올바른 identity와 qualification을 확인한다고 가정한다.

## 8. 핵심 객체와 데이터 구조

- DID와 DID document
- Identity·qualification VC
- Private product specification
- Private transaction amount
- Compliance policy와 ZK proof
- Transaction state record

## 9. 전체 동작 과정

Authority가 credential을 발급하고, 거래 당사자가 credential과 private transaction data를 witness로 사용해 compliance proof를 만든다. Smart contract는 proof를 검증하고 transaction state를 갱신한다.

## 10. 암호 기술과 사용 목적

- DID·VC·signature: identity와 qualification authenticity
- Public-key encryption: sensitive transaction field 보호
- ZKP: credential과 private field가 policy를 만족함을 검증
- Blockchain: verification result와 transaction state 기록

## 11. 논문이 제공하는 보장

Credential authenticity와 compliance predicate를 함께 검증하고, verifier는 underlying identity·specification·amount를 직접 받지 않는다.

## 12. 데이터 신뢰성과 Consistency 확보 방식

ZKP witness가 실제 authoritative data인지 확인하기 위해 issuer-signed VC를 circuit relation에 포함한다. Consistency 대상은 transaction policy와 credential claim이며 제조 Event 사이의 quantity accounting은 아니다.

## 13. Privacy, 기원 추적과 CoC

Identity, qualification, product specification, amount가 privacy target이다. Blockchain에는 proof와 transaction state가 남는다. CoC 전체를 재구성하는 provenance Scheme은 논문의 중심이 아니다.

## 14. 구현과 성능 평가

Shipbuilding supply-chain transaction 사례와 100-node private blockchain에서 gas, execution time, memory overhead를 평가한다. Plain smart contract, encryption-based flow와 end-to-end performance도 구분해 제시한다.

## 15. 연구 목표 안에서의 강점과 주의점

ZKP가 witness truthfulness를 자동으로 만들지 않는다는 점을 명시하고 VC issuer를 input-authenticity layer로 둔 것이 강점이다. 전체 신뢰성은 issuer와 policy authority의 운영에 의존한다.

## 16. Matrix 분류값

- 1차 분류: Supply Chain Scheme
- Verification statement: credential-backed transaction compliance
- Privacy target: identity, qualification, specification, amount
- Consistency: VC authenticity + policy relation
- Provenance: transaction audit record

## 17. 중립적인 인용 문장 후보

ZKVeil은 DID와 VC로 거래 input의 발급자를 확인하고, ZKP로 private identity·product specification·amount가 supply-chain compliance policy를 만족하는지 검증한다.
