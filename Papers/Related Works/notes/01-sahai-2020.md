## 3. 한 문장 요약과 전체 흐름

공급망 작업을 서로 연결된 private document로 표현하고, 문서 원문을 공개하지 않은 채 ZKP로 Event별 input-output relation을 검증하며, RSA accumulator로 전체 upstream provenance를 요약한다.

전체 흐름은 `문서 작성 → 문서 commitment 생성 → Event relation proof 생성 → ledger 검증·등록 → upstream accumulator 갱신` 순서다.

## 4. 해결하려는 문제와 연구 목표

Blockchain에 공급망 기록을 그대로 공개하면 거래 상대, 수량, 제조 관계와 같은 영업 정보가 노출된다. 반대로 정보를 감추기만 하면 제품 provenance와 오염 Lot 포함 여부를 검증하기 어렵다.

논문은 Split, Merge, Process가 반복되는 실제 공급망을 문서 graph로 모델링하면서 다음을 동시에 제공하려 한다.

- 문서 내용의 비공개성
- 제품 provenance 추적
- 공개 기록만으로 참여자의 거래를 연결하기 어렵게 하는 unlinkability
- 전체 중간 이력을 열지 않는 contamination tracing

## 5. 저자가 주장하는 핵심 기여

1. 공급망 문서를 constant-size on-chain commitment로 기록한다.
2. Entry, Ship, Merge, Split, Process, Exit을 문서 유형으로 모델링한다.
3. ZKP로 숨겨진 문서 사이의 관계를 검증한다.
4. RSA accumulator로 모든 upstream 문서의 집합을 요약한다.
5. Hyperledger Fabric과 libsnark로 구현하고 payload 생성·검증 비용을 측정한다.

## 6. 시스템과 lifecycle 범위

원자재 Entry부터 최종 Exit까지의 생산·이동 공급망을 다룬다. 사용, 수리, 재사용, 재활용과 같은 소비 이후 lifecycle은 논문의 중심 범위가 아니다.

## 7. 등장 주체와 신뢰 가정

- 공급망 참여자: 문서를 만들고 소비하는 sender와 recipient
- Permissioned blockchain peer: transaction과 proof 검증
- Identity issuer: 등록 참여자임을 증명하는 anonymous credential 제공
- 최종 검증자: provenance 또는 contamination 여부 확인

최초 Entry 정보와 실제 물품의 일치는 신뢰된 등록자에게 의존한다. 수령자는 off-chain으로 받은 문서와 실제 물품이 일치할 때만 다음 작업을 진행한다고 가정한다.

## 8. 핵심 객체와 데이터 구조

- `DocInfo`: Item, Sender, Recipient, Quantity 등 실제 문서 내용
- `DocHash`: salted Merkle root로 만든 문서 commitment
- `InDocs`: 현재 문서가 직접 소비한 이전 문서 ID
- `DocPrime`: RSA accumulator에 넣는 문서의 prime identifier
- `DocAccumulator`: 현재 문서의 모든 upstream 문서 집합을 요약
- Supply-chain graph: document가 vertex이고 소비 관계가 directed edge인 DAG

## 9. 전체 동작 과정

1. Client가 소비할 input document를 선택한다.
2. Event 유형에 맞는 output `DocInfo`를 작성한다.
3. `DocHash`, `DocPrime`, `DocAccumulator`를 계산한다.
4. 숨겨진 input과 output이 Event relation을 만족한다는 proof를 만든다.
5. Merge·Process에서는 input accumulator의 결합 관계도 증명한다.
6. Chaincode가 proof와 prime certificate를 검증한다.
7. 검증된 output document asset을 ledger에 추가한다.

## 10. 암호 기술과 사용 목적

| 기술 | 사용 목적 |
|---|---|
| Salted Merkle commitment | `DocInfo` 은닉과 attribute opening |
| zkSNARK | 비공개 attribute의 equality, addition, conjunction, Merkle path 검증 |
| RSA accumulator | 전체 upstream 문서 집합의 constant-size 요약 |
| Membership·non-membership proof | 오염 문서가 provenance에 포함되거나 포함되지 않음을 검증 |
| Anonymous credential | 등록된 참여자임을 보이면서 transaction identity 연결을 완화 |

## 11. 논문이 제공하는 보장

- 문서 template의 private value를 공개하지 않고 Event relation 검증
- ledger의 document graph와 실제 문서 소비 관계의 대응
- 특정 문서가 최종 제품의 upstream에 속하는지 검증
- transaction 공개정보만으로 동일 참여자 또는 recipient를 식별하기 어렵게 하는 privacy 목표

## 12. 데이터 신뢰성과 Consistency 확보 방식

이 논문은 단순 Hash anchoring에 머물지 않는다. `DocHash`는 내용을 고정하고, ZKP는 Event별 input-output relation을 검사한다. Quantity는 Merge와 Split에서 addition relation으로 연결된다. `InDocs`와 accumulator는 direct edge와 transitive upstream set을 각각 고정한다.

다만 실제 물품과 최초 입력 데이터의 진실성은 암호 proof만으로 생성되지 않는다.

## 13. Privacy, 기원 추적과 CoC

문서 원문은 private이고, ledger에는 commitment와 proof가 기록된다. Provenance는 `InDocs`와 accumulator로 유지된다. 논문의 CoC는 document consumption graph에 가깝고, sustainability attribute accounting을 일반적으로 정의하는 체계는 아니다.

## 14. 구현과 성능 평가

- Hyperledger Fabric v2.0, Go chaincode, libsnark
- 실험 환경: Intel i7-4770, 8 cores, 32 GB RAM, Ubuntu 18.04
- Multi-thread payload 생성: Entry 6.2초, Ship 13.4초, Merge 19.2초, Split 19.2초
- Chaincode 실행: Entry 71 ms, Ship 176 ms, Merge 211 ms, Split 212 ms, Exit 70 ms
- Process는 논문 평가에서 Merge와 같은 비용으로 처리한다.

## 15. 연구 목표 안에서의 강점과 주의점

강점은 supply-chain Event를 private document relation으로 명시하고, direct provenance와 transitive provenance를 서로 다른 객체로 처리한 점이다.

주의할 점은 Process relation이 산업별 제조 규칙을 표현하지 않고 Merge와 같은 기본 relation으로 평가된다는 점이다. 또한 1024-bit RSA modulus와 당시 SNARK 구현 수치는 현재 보안·성능 기준으로 그대로 재사용하기보다 구조 이해용으로 봐야 한다.

## 16. Matrix 분류값

- 1차 분류: Supply Chain Scheme
- Product representation: private supply-chain document
- Manufacturing transition: Event-specific document relation
- Provenance: `InDocs` graph와 upstream accumulator
- Privacy target: document value, participant linkage, recipient
- Consistency: commitment + ZKP relation + accumulator

## 17. 중립적인 인용 문장 후보

Sahai et al.은 공급망을 문서 소비 관계로 구성된 DAG로 모델링하고, 문서 내용을 commitment로 숨긴 상태에서 ZKP로 Event별 relation을 검증하며 RSA accumulator로 upstream provenance를 요약하였다.
