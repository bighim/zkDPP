\needspace{8\baselineskip}\section*{1. 기본 성능}
\textbf{기본 설정}\newline
State는 3개입니다.\newline
Audit을 사용합니다.\newline
Process의 기본 입출력은 2$\rightarrow$1입니다.\newline
Issue에는 Standard Policy를 사용합니다.\par\smallskip
\textbf{반복 기준}\newline
입력 Note / path / Policy를 확보한 뒤 측정을 시작합니다.\newline
각 case는 warm-up 1회 후 공식 5회 실행합니다.\newline
표에는 공식 5회의 \textbf{median}을 표시합니다.

\textbf{Event E2E}\newline
참여자가 해당 Event의 witness를 준비할 때부터 측정합니다.\newline
Proof를 생성하고 transaction을 구성 / 제출합니다.\newline
성공 receipt를 확인하면 측정을 끝냅니다.\newline
로컬 Verify와 사후 상태 대조는 이 시간에서 제외합니다.\par\smallskip
\textbf{Gas}\newline
해당 Event를 제출한 계정의 실제 Anvil transaction \textbf{gasUsed}입니다.\newline
온체인 Proof 검증과 상태 변경 비용을 포함합니다.\newline
Contract 배포 비용은 포함하지 않습니다.

\par\noindent\begin{minipage}{\linewidth}
\subsection*{직접 전달과 Voucher 전달 / 반환}
\textbf{고정 조건}\newline
세 경로 모두 Audit을 사용하지 않습니다.\newline
입력 State / 전달량 / 운송 탄소 / Change 규칙을 동일하게 맞췄습니다.\par\smallskip
\textbf{비교 경로}\newline
직접 Transfer는 Receiver Note를 바로 생성합니다.\newline
Transfer $\rightarrow$ Proceed는 Voucher를 거쳐 Receiver Note를 생성합니다.\newline
Transfer $\rightarrow$ Recall은 Voucher를 거쳐 Sender에게 Note를 반환합니다.\par\smallskip
\textbf{경로 E2E}\newline
첫 Transfer의 witness 준비부터 측정합니다.\newline
직접 전달 / 수령 / 반환 중 해당 경로의 마지막 성공 receipt에서 끝납니다.\newline
로컬 Voucher 전달과 최신 path 확보도 포함합니다.\par\smallskip
\textbf{총 Gas}\newline
해당 경로에서 실제 실행한 모든 transaction의 gasUsed를 합산합니다.\par\smallskip

\par\noindent\begin{minipage}{\linewidth}
\subsection*{Tracing 기록 수 / 분기 구조와 Freeze 비용}
\textbf{시간 단위는 초(s)}입니다.\par\smallskip
\textbf{시작점과 대상}\newline
Forward는 최초 cm에서 시작합니다.\newline
Backward는 가장 깊은 최종 Note에서 시작해 조상을 찾습니다.\newline
두 Tracing은 복구된 Master Key와 확보한 Snapshot을 사용합니다.\newline
각각 Tracing을 시작해서 완료할 때까지 측정합니다.\newline
키 복구와 Snapshot 확보 시간은 두 열에 포함하지 않습니다.\newline
대상 수는 동결할 미소비 / Active Note/Voucher의 수입니다.\par\smallskip
\textbf{Freeze와 전체 시간}\newline
Freeze는 이미 찾은 대상의 동결 처리를 시작할 때부터 측정합니다.\newline
제출 전 상태 검사와 동결 transaction 실행을 포함합니다.\newline
공통 Snapshot에서 최종 상태를 확인하면 끝납니다.\newline
전체는 Master Key 복구부터 시작하는 \textbf{AuditAndFreeze} 시간입니다.\newline
Snapshot 확보 $\rightarrow$ Forward $\rightarrow$ Freeze $\rightarrow$ 최종 확인을 포함합니다.\newline
Backward는 전체 시간에 포함하지 않습니다.\par\smallskip

\textbf{비교 방법}\newline
같은 구조의 행끼리 비교하면 기록 수 증가의 영향을 볼 수 있습니다.\newline
같은 기록 수에서 연속 Split과 균형 Split을 비교하면 분기 구조의 영향을 볼 수 있습니다.\newline
Split $\rightarrow$ Merge는 11/101/1,001개입니다.\newline
다른 두 구조의 10/100/1,000개와 정확히 같은 기록 수는 아닙니다.\par\smallskip
\textbf{반복 조건}\newline
각 감사는 빈 cache에서 시작합니다.\newline
같은 graph의 읽기 전용 Tracing은 고정 Snapshot에서 반복합니다.\newline
Freeze는 매회 대상들을 같은 미소비 / Active 상태로 되돌린 뒤 실행합니다.\newline
graph 구축과 Proof 준비 시간은 제외합니다.\par\smallskip
\textbf{해석할 때 주의할 점}\newline
Backward는 전체 기록이 아니라 시작 Note의 조상만 방문합니다.\newline
각 열은 따로 측정한 시간의 median입니다.\newline
따라서 각 열을 더한 값이 전체 시간과 같지는 않습니다.
