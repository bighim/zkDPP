# Abstract·Introduction 윤문본

목적은 문장별 비평이 아니라 **논문의 문제·필요성·설계·기여가 하나의 흐름으로 이어지는지 읽고 판단하는 것**입니다.
기존 `../zkdpp-v0.2-260916/` 파일은 수정하지 않았습니다.
원문과 검토 의견 중 **원문을 기준**으로 윤문했으며, 아직 합의되지 않은 검토 제안을 원문의 확정 주장처럼 추가하지 않았습니다.

## 읽을 파일

- `00.Abstract.tex`: 국문 요약 윤문본
- `01.Introduction.tex`: 1.1~1.4 윤문본
- `main.tex`: 위 두 파일을 직접 불러오는 문서
- `main.pdf`: 읽기용 PDF

영문 Abstract는 번역 대조 대상이므로 이번 국문 윤문본에는 포함하지 않았습니다.
인용 번호 [1]~[5]는 유지했으며, 서지는 원문 프로젝트의 `13.References.tex`에서 확인할 수 있습니다.

## 큰 흐름

1. **1.1 — 검증할 문제:** DPP의 주장에는 공급망의 증빙과 후속 계산이 필요하며, 두 검증은 다르다.
2. **1.1 — 공개 범위:** 거래의 규칙 준수는 검증하되 상세 수치와 공급 관계는 일반에 공개하지 않는다.
3. **1.2 — 사후 대응:** 계산이 맞더라도 입력 증빙에 나중에 오류가 발견될 수 있으므로, 후속 기록의 사용을 제한할 절차가 필요하다.
4. **1.3 — 연구 과제:** 거래에서 검증한 근거·Claim 발급 상태·감사로 복원한 연결·소비 차단 대상을 일치시켜야 한다.
5. **1.4 — 제안:** 증명에 결합된 감사 정보, 승인된 복호화, 대상별 동결과 공통 시점의 완료 판정을 연결한다.

## 그대로 유지한 범위

- 원천 증빙의 진실성은 외부 공급·검사·감사 절차가 판단한다.
- 감사자를 신뢰하며, 데이터 키를 별도 임계 암호화로 보호하는 원문의 두 키 구성을 유지한다.
- 차단은 미소비 원장 객체의 후속 소비에 적용하며, 기발급 Claim 취소나 물리적 회수를 뜻하지 않는다.
- 공통 시점의 전체 대상 확인과 소비 경합·불명확 결과의 미완료 처리를 유지한다.
- Privacy는 명시한 가정과 수동 외부 관찰자 범위로 제한한다.
- 구체 암호·실제 구현·성능을 검증하지 않았다는 원문의 평가 범위를 유지한다.

## 이번 작업에서 하지 않은 일

법령과 관련연구의 실질적 주장을 외부 원문과 새로 검증하거나, 보안 증명이 타당하다고 판정하지 않았습니다.
현재 POC의 구현·성능을 이 논문의 검증 결과로 추가하지 않았습니다.
논문의 주장 자체를 수정해야 하는지는 이 윤문본을 읽으며 별도로 논의합니다.
