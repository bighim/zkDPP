\section{보안 증명의 세부사항}
\label{app:security-details}

이 부록은 \ref{sec:analysis}절의 세 정리에 사용한 실험과 암호 가정을 명시한다.
모든 공격자와 실행·객체·증명·질의 수는 보안 매개변수 $\lambda$의
다항식으로 제한한다. 확률은 명시한 전체 실행에 관한 것이다.
원장의 권한·인증·확정·현재 상태 집행과 신뢰된 감사자의 동작을
모델 전제로 둔다.

\subsection{정확성 증명}
\label{app:correctness-details}

정확성 게임은 정직한 생성에 사용한 증인을 보관한다.
거래는 전체 증명 관계와 실행 조건, 출력 신규성과 트리 용량을
만족하며 그 조건이 실행까지 유지되어야 한다.
공개 DPP 검증은 발급이 포함된 확정 이력과 그 발급에 맞는 정규 문서를 쓴다.
추적은 유효 시작점·확정 $H_t$·유효 감사키를 사용하고,
필요한 유한 기록과 종료하는 인증 조회가 있어야 한다.
고정 $H_t$의 조회에는 그 이후 원장 전체의 무경합을 요구하지 않는다.

차단 승인이 있고 정확한 전체 $T$가 비어 있지 않다면,
$H_t$부터 $H_r$까지 대상 소비와 차단 해제가 없어야 한다.
Active 대상의 합법적 동결, 모든 제출 결과·조회,
사용한 관찰을 반영하는 같은 확정 이력의 $H_r$을 정한 유한 한도
안에서 확보해야 한다. $T=\varnothing$에는 이 추가 조건 없이
빈 대상 분기를 적용한다.

위 조건이 성립하는 요청에서 기대한 결과를 내지 못하면
$\mathsf{Fail}_{\rm corr}$를 기록한다. 조건이 깨져 정상 거부하거나
\Alg{INCOMPLETE}인 실행은 이 사건이 아니다.
정리 1은 정상 조건과 실패가 함께 발생하는 전체 실행 확률의 상계다.
정상 조건을 만족한 실행만 고른 조건부 실패 확률과 구분한다.
증명 완전성 실패 밖에서는 정직 증명이 수락되고 원자적 상태 갱신이
정해진 결과를 기록한다. 복호화 실패 밖에서 실제 부모·미래 식별자를
얻고 관련 해시 충돌 밖에서 다른 객체의 식별자는 구별된다.

부록~\ref{app:trace-details}의 경로를 정직 생성 목록에 적용하면
그래프·미소비 집합·종단이 정확하다.
증인을 이미 알고 있으므로 정확성에는 악의적 증인의 추출이 필요 없다.
동결의 추가 조건은 전체 $T$와 공통 시점의 완료 검사를 만족시킨다.
따라서 실패는 완전성·복호화·관련 충돌의 합집합에 포함되고,
정리 1의 전체 실행 상계가 따른다.

\subsection{건전성 증명}
\label{app:soundness-details}

보안 강도의 기준값인 보안 매개변수 $\lambda$를 두고,
그 값에 대한 다항 길이 실행을 고려한다.
공격자는 정상 거래를 관찰하거나 만들게 하고,
이전 결과를 본 뒤 다음 행동을 고를 수 있다.
임의의 공개 입력과 증명 $(x,\pi)$도 제출한다.
확정된 과거 이력과 문서·Claim에 대해 공개 검증 절차인
\Alg{CheckDPP}도 질의한다. 원장은 고정된 전체 관계의 검증키로 증명을 확인하고 현재
권한·정책·미소비·활성·기한·출력 신규성을 검사한 뒤 원자적으로
갱신한다. 수락 이력의 의미적 유효성은 아래의 귀납 논증으로 보인다.

나중에 제출된 값이 실제 생성값과 같은지 비교하려면
처음 생성된 값을 기준으로 남겨야 한다.
이를 위해 분석용 생성 목록 $\mathcal C$에 객체가 처음 수락됐을
때의 전체 개방값과 타입별 미래 식별자를 고정한다. 정직 생성에는 원래 증인,
공격자 수락에는 추출 증인을 사용하며 식별자에서 생성 객체로 가는
역대응도 고정한다.
실패 사건 $\mathsf{BadSem}$은 수락 입력이 먼저 생성되지 않았거나,
생성 개방값과 다른 값을 사용하거나, 그 실제 값에 대한 소유 비밀·
정수 회계·정책 관계 또는 현재 상태 검사가 거짓인 경우다.
반복 계상·소비, 잘못된 상태 갱신, 실제 부모·미래 식별자와 다른
감사 복호화도 포함한다. 공개 DPP는 인증된 발급 기록과 입력
문서 해시·정책·논스의 불일치를 실패로 정의한다.
추출 실패나 모호한 역대응에서는 분석 게임이 실패를 기록하고
종료한다. 그 밖에서만 실제 생성 목록과 의미 위반을 비교한다.

공격자는 수락 이력의 유효 시작점·확정 시점·방향을 골라 추적을
실행하게 할 수 있다. 차단 승인이 있는 후속 추적에는 신뢰된 상태
관리자가 \Alg{AuditAndFreeze}를 수행한다. 공격자는 허용된 전이·
합법적 상태 변경·자료 오류를 스케줄하며 감사 이후의 전이까지
전체 실행 예산에 포함한다. 인증 조회는 실제 값 또는 오류만
제공하고, 임의 권한 변경이나 새로운 키 공개 질의는 주지 않는다.

통합 게임 $\mathsf{Exp}_{\rm sound}$는 위 전이·DPP 의미 위반,
잘못된 추적 성공, 또는 완료 반환과 완료 술어/차단 유지 구간의
위반이 함께 생기면 1을 반환한다. 자료 부재의 명시적 실패나 전체
대상을 보존한 \Alg{INCOMPLETE}는 공격 성공이 아니다. 아래 나쁜
사건에서는 1로 종료하고 그 밖에서만 생성 목록과 결과를 비교한다.

증인 추출·결합·포함 관계·해시·복호화에 다음 계약을 적용한다.
\begin{enumerate}
 \item 정직한 증명의 관측·재전송과 다수 등록 관계를 포함하는
 적응적 실행의 수락 증인을 공동 추출하는 PPT 알고리즘이 있다.
 추출은 분석용 권한으로 증명의 근거 입력을 얻는다는 뜻이다.
 비공개 추출 보조키(trapdoor) 또는 명시된 공격자 접근 권한을 가지며
 그 권한은 분석용 추출기에만 제공한다. 공개 실행 기록의 분포는 실제 실행과
 같거나 통계적으로 가까우며 그 오차도 전체 실패 상계
 $\epsilon_X$에 포함한다. 추출 보조정보는 독립 원시기술의
 도전 실험의 비밀을 주지 않아야 한다. 정직한 동일 증명
 재전송에는 원래 증인을 쓴다.
 \item 정규 전체 개방값의 계산적 결합성, 수락된 루트의 포함
 관계의 건전성, 소유자·객체·식별자·Claim 해시의 충돌 저항성에
 대한 전체 실행 상계를 각각 $\epsilon_C,\epsilon_M,\epsilon_H$라
 둔다. $\epsilon_H$는 추출된 증인에서 얻는 서로 다른 정규
 소유 비밀의 소유자 해시 충돌도 포함한다.
 \item 고정 키와 벡터 형식에서 모든 허용 평문과 \emph{증명자가 선택한}
 유효 난수에 대해 복호화가 정확하다. 완전 정확성이면 실패는 0이며,
 완화할 경우 적대적 난수 선택의 실패 상계를 $\epsilon_E$로 둔다.
\end{enumerate}

기반 지식 건전성의 문헌 근거로 PLONK 원문의 \S2.2,
Lemma 4.7과 Corollary 7.2를 사용한다~\cite{gabizon-plonk-2019}.
대수적 군 모형은 공격자가 생성한 군 원소의 대수적 표현을
분석용 추출기에 제공하며, 원문은 이 모형과 차수에 따른
이산로그 가정 아래 지식 건전성을 제시한다.
위 첫 계약은 이 성질을 정직 증명·재전송·여러 등록 관계를
포함한 전체 수락 이력에 적용할 때 사용하는 추출 조건이다.

\emph{증명: 전이와 감사 결합.}
추출·결합·포함 관계·관련 충돌·복호화 계약의 실패 합집합을
$\mathsf{Bad}$라 두면 $\Pr[\mathsf{Bad}]\leq\epsilon_B$다.
이 중 어느 실패도 일어나지 않은 실행을 생각한다.
앞서 수락된 기록이 올바르면 다음 거래도 그 기록을
올바르게 사용해야 함을 수락 순서대로 보인다.
추출 입력의 포함 증인은 이전 실제 등록 객체를 가리킨다.
생성 목록의 개방값과 다르면 계산적 결합성의 명시적 충돌 쌍이다.
따라서 추출 증인의 타입·정수·소유권·정책 관계가 바로 최초
생성 값에 적용된다.

Note의 생성·소비 개방값은 같은 $cm,owner$를 포함한다.
생성 때의 비밀을 $s$, 소비 증인의 비밀을 $s'$라 하면,
소유권 관계는 $H_{\mathsf{Owner}}(s)=owner=H_{\mathsf{Owner}}(s')$를 준다.
$s\ne s'$이면 공동 추출로 확보한 두 정규 입력은 소유자 해시의
명시적 충돌 쌍이다. 이 사건은 $\epsilon_H$에 포함되므로,
나쁜 사건 밖에서는 $s=s'$이고 결정적 $nf$도 같다.
Voucher는 결합된 같은
개방 난수에서 $rvnf$를 얻으므로 인수·회수도 동일하다.
다른 같은 타입 객체의 식별자 중복은 서로 다른 참조가 포함된
정규 해시 입력의 충돌이다. 이에 따라 타입별 현재 소비·상태
검사가 바로 실제 객체에 적용된다. 중복 입력 검사와 원자적
소비 기록은 반복 계상과 경합 재소비를 거부한다.

감사 관계는 이 실제 입력·출력의 부모·미래 식별자를 같은 증인으로
한 벡터로 암호화한다. 고정 키와 전체 목록의 위치별 복호화 정확성으로
감사자는 같은 평문을 얻고, 거래 형상으로 참조의 타입을 복원한다.
이는 증명자가 고른 모든 허용 난수에도 적용한다. 다른 문서 해시·정책·논스를 기존
등록 Claim에 붙여 유효 판정을 받으면 Claim 결합 해시의 충돌이다.
따라서 실패 합집합 밖에서는 $\mathsf{BadSem}$이 없고,
같은 나쁜 사건 밖에서 추적·차단을 분석할 수 있다.

\paragraph{추적과 전체 대상의 차단.}
실제 그래프는 위 생성 목록으로 부록~\ref{app:trace-details}처럼 정의한다.
공격자는 수락 이력 뒤 확정 시점·유효 시작점·방향과 자료 오류를 고른다.
인증 조회는 그 시점의 실제 값 또는 오류만 제공하고 감사자에게
유효한 키를 준다. 나쁜 사건에서는 실패를 기록하고,
그 밖에서는 성공 반환이 실제 그래프·미소비 집합·종단과 다른지 비교한다.

부모 복호화는 실제 입력을, 미래 식별자는 실제 소비 이벤트를 가리킨다.
시작점에서 한 단계 확장이 맞으면 다음 단계도 맞으므로,
경로 길이에 대한 귀납으로 추적 결과의 일치를 얻는다.
재방문에서도 새 간선을 남기므로 분기·합류에서 경로를 잃지 않는다.
필요한 자료가 가용하고 조회가 종료하면 유한 그래프의 추적도 끝난다.

완료 게임에서는 공격자가 합법적 거래·상태 변경과 자료 오류를
스케줄하고 신뢰된 상태 관리자가 실제 \Alg{AuditAndFreeze}를 실행한다.
감사 이후 이벤트도 전체 실행 예산에 포함한다.
공통 $H_r$은 같은 확정 이력에서 사용한 관찰·영수증을 반영한다.
정확한 전체 $T$에 식~\eqref{eq:frontier-cut}가 성립하면,
$H_t$ 뒤 최초의 후속 소비는 $T$의 객체를 써야 한다.
그러면 그 불변 소비 기록이 $H_r$에서 0일 수 없어 모순이다.
$H_r$ 뒤에도 차단이 유지되면 현재 상태 검사가 첫 소비를 거부한다.

완료를 반환했으면서 완료 술어가 거짓이거나 유지 구간의 차단 함의가
깨지는 사건을 $\mathsf{BadComplete}$라 하자.
위 결정적 함의로 $\Pr[\mathsf{BadComplete}]\leq\epsilon_B$를 얻는다.
상계는 나쁜 사건을 포함한 전체 실행에 관한 것이며
완료에 조건을 건 확률로 바꾸지 않는다.
전이·추적·완료의 실패는 같은 나쁜 사건에 포함되므로
정리 2의 $\epsilon_B$를 세 번 더하지 않는다.

\subsection{프라이버시 증명}
\label{app:privacy-details}

\paragraph{감사 암호화의 문헌 근거와 적용 조건.}
식~\eqref{eq:audit-vector-encryption}은 DH 공유 점에서 키를 유도하고
그 키로 평문 벡터를 마스킹하는 hybrid ElGamal 구성이다.
대칭암호 부분은 $E_s(k_{\rm sym},M)_j=M_j+
H_{\mathsf{AuditMask}}(k_{\rm sym},j)$로 대응한다.
기반 암호화의 IND-CPA는 Boneh--Shoup \S11.5의
Remark 11.1과 Theorem 11.5를 인용한다~\cite{boneh-shoup-2020}.
문헌의 군·키 유도·대칭암호 전제를 충족하는 구성에서 이 결과를 적용한다.
여기서는 두 감사 해시를 서로 독립된 고전적 무작위 오라클로 두고,
출력 영역은 최소 $2^\lambda$, 위치 인코딩은 단사로 둔다.
대칭 부분에는 새 키로 한 벡터를 암호화하는 일회용 기밀성을 요구하며,
각 이벤트는 독립 정직 난수를 사용한다.
문헌과 허용 스칼라 영역이 다르면 그 조건화 차이도 기본 게임의 비용에
포함한다. 평가의 Jubjub·Poseidon2는 이 분석에 대응하는 구현 선택이다.

\paragraph{감사 암호화의 관측 범위와 기밀성.}
하나의 감사 비밀키 $SK_B$를 Shamir 방식으로 분산하고,
공개키 $PK_B$와 모든 공개 조각 확인 자료 $V_i$를 제공한다.
관찰자는 설정 전에 $|I|<K$인 노출 집합 $I$를 고정하며,
그 집합의 실제 비밀 조각도 받는다. 배포·구성원·키 descriptor의
인증은 공개 자료와 독립 인증키로 재현 가능한 후처리로 두고
추가 비밀 의존 정보는 주지 않는다.
원본 키 사본 폐기와 외부 조각 전달의 인증·비밀성은 신뢰 경계다.

공개키 암호화의 IND-CPA는 같은 길이의 두 평문 중 어느 것을
암호화했는지 구별하기 어렵다는 성질이다~\cite{boneh-shoup-2020}.
여기서는 위 공개 확인 자료와 정적 노출 조각을 포함하는 다음
다중 암호문 게임의 기밀성을 요구한다.
공통 비트 $b$를 정하고, 관찰자가 이전 관측에 따라 최대 $m$개의
같은 길이 평문 쌍 $(M_e^0,M_e^1)$을 고르면
각각 독립 정직 난수 $r_e$로
$\mathsf{AuditEnc}(PK_B,M_e^b;r_e)$를 돌려준다.
길이·타입·배열 분할 등 공개 형상은 양쪽에서 같다.
공개키로 직접 암호화하는 계산, 공개 오라클 평가와 로컬 검증은
허용하고, 추가 조각·키 복원·복호화 질의는 제공하지 않는다.
기밀성 이득은 두 비트 실험에서 1을 출력할 확률의 절댓값 차이다.
이 정의는 비밀 조각 노출을 게임에 명시하여 포함한다.

이 게임에서 $M_e^0=M_e$, $M_e^1=0^{d_e}$로 두었을 때의
전체 이득 상계를 $\epsilon_{\rm Aud}$라 한다.
$d_e$는 실제 감사 벡터의 길이이며, 영 벡터는 같은 평문 공간의
고정 더미다. 공개 형상과 공통 설정은 유지하고 더미도 정직한
새 난수로 암호화한다. 환원이 생성한 객체 비밀·개방값과 공개
후처리·증명 시뮬레이터의 평가 질의를 포함하는 아래 공동 모형에서
이 상계를 사용한다. 이 보조정보의 생성은 감사키 비밀·암호화 난수와 독립이다.
단일 도전의 같은 관측 게임 이득을 $\epsilon_{\rm cpa}$로
상계하면 최대 $m$번의 치환으로 $\epsilon_{\rm Aud}\leq
m\epsilon_{\rm cpa}$를 쓸 수 있다. 전체 게임 상계에는 이 계수를
다시 곱하지 않는다.

\paragraph{공개 확인 자료·노출 조각과 기본 게임의 연결.}
소수 위수 $\ell$의 군에서 $PK_B=xG$이고,
$x$는 기본 공개키 게임과 같은 비영 균등 스칼라다.
Shamir 다항식은 $f(0)=x$, 차수 $K-1$ 이하이며,
구성원 식별자는 서로 다른 비영 원소다($N<\ell$).
비밀 조각은 $s_i=f(i)$, 공개 확인 값은 $V_i=s_iG$다.
먼저 나머지 $K-1$개 계수를 $\mathbb F_\ell$에서 독립 균등으로
뽑는 이상적 설정을 생각한다.

설정 전에 고정된 노출 집합 $I$를 포함하는 크기 $K-1$의 집합 $J$를
고르고 각 $y_j$를 $\mathbb F_\ell$에서 독립 균등으로 뽑는다.
$K=1$이면 $J$는 비어 있다.
평가점 $\{0\}\cup J$의 Lagrange 기저를 $L_0,L_j$라 하면
\begin{equation}
 \begin{aligned}
 f(t)&=L_0(t)x+\sum_{j\in J}L_j(t)y_j,\\
 V_i&=L_0(i)PK_B+\sum_{j\in J}L_j(i)y_jG.
 \end{aligned}
 \label{eq:audit-share-simulation}
\end{equation}
따라서 환원은 $x$를 몰라도 기본 게임에서 받은 $PK_B$만으로
모든 $V_i$를 계산하고, $i\in I$의 비밀 조각으로 $y_i$를 제공한다.
고정 $x$에서 $K-1$개 평가값과 다항식 계수 사이의 변환은 가역이므로,
이 자료의 공동 분포는 이상적 설정과 정확히 같다.
descriptor도 독립 인증키를 쓰는 공개 후처리로 재현한다.
관찰자가 고른 평문 쌍을 기본 IND-CPA 질의에 전달하고 반환 암호문을
그대로 주며, 허용된 독립 보조정보와 시뮬레이터 후처리는 같은 공동
모형에서 실행한다. 이 과정에 $x$나 도전 난수는 필요하지 않다.
따라서 이상적 설정의 구별 이득은 기본 다중 암호문 IND-CPA 이득으로
상계된다.

실제 조각 설정과 이상적 설정의 전체 공동 분포 사이 통계적 거리를
$\delta_{\rm set}$이라 하자. 이상적 표본 전체를 비영 계수·조각만
허용하도록 조건화하는 거부 표본화라면 합집합 상계로
$\delta_{\rm set}\leq(K-1+N)/\ell$을 얻으며,
이상적 설정 자체에서는 $\delta_{\rm set}=0$이다.
동일한 허용 키·정직 난수 구성의 기본 다중 암호문 비용을
$\epsilon_{\rm PKE,m}$이라 두면
\begin{equation}
 \epsilon_{\rm Aud}\leq\epsilon_{\rm PKE,m}+2\delta_{\rm set}.
 \label{eq:audit-indcpa-connection}
\end{equation}
두 비트 실험을 각각 실제 설정에서 이상적 설정으로 바꾸는 차이가
$\delta_{\rm set}$ 이하여서 계수 2가 붙는다.
이 차이는 $\epsilon_{\rm Aud}$에 포함하며 원장 정리에서 다시 더하지 않는다.

\paragraph{원장 구별 게임.}
객체·식별자의 다섯 해시 영역은 서로 독립된 고전적 무작위
오라클로 두며 감사 암호화의 내부 해시와 분리한다.
출력 영역은 최소 $2^\lambda$, 개방 난수와 정규 소유 비밀의
독립 균등 영역은 최소 $2^\kappa$이다. $\kappa$는 이 영역 크기의
하한을 비트 단위로 나타내며 $\lambda$에 선형으로 증가한다.
감사키·분산 계수·객체 비밀·암호화 난수는
독립이다. 소유 비밀 재사용은 허용하되 별도 공개 OwnerKey는 주지 않는다.
공개 호출자·서명키는 보호 비밀과 독립이다.

공개 설정·노출 조각을 본 공격자는 두 의미적 이력 $h_0,h_1$을 고른다.
이력은 회계 값·소유자 이름·부모 연결을 지정하지만 비밀·난수는
지정하지 않는다. 독립 정직 난수로 유효하게 실현하는 다항 시간
생성기가 있어야 하며, 난수·해시 비트에 따른 선택적 수락이나
재표본화를 요구하는 이력은 제외한다.
공개 누출 $L(h_0)=L(h_1)$을 검사하고 비트 $b$의 이력을 실현한다.
공격 이득은 양쪽에서 공격자가 1을 출력할 확률의 절댓값 차이다.

$L$은 종류·정책·scope·입출력 타입·수·순서·sibling 관계·
호출자·시간·기한·루트의 접두 이력 위치·벡터 길이·배열 분할,
공개 객체와 소비 식별자의 타입별 표지·색인·동일성 패턴,
공개 Claim의 문서·정책·논스 의미와 외부 공개 정보를 포함한다.
비공개 생성 참조에서 미래 소비 식별자로 가는 대응을 자동
연결하지 않으며, 원시 커미트먼트·암호문 바이트의 동일성을 요구하지 않는다.
공개 문서 후보의 대입으로 얻는 정보도 공개 누출에 포함한다.

관측은 설정·조각·원장·암호문·증명 전체를 포함한다.
공개 오라클 질의와 로컬 검증은 허용하지만 추가 조각,
참여자 비밀·개방값·$SK_B$·키 복원·복호화·능동 거래 제출·
보호 관계의 감사/상태 공개 질의는 주지 않는다.
허용되지 않는 이력 쌍은 $b$와 무관하게 거부한다.
유효 생성에 필요한 참조·식별자 충돌 예외는 아래 $\epsilon_{\rm id}$에 포함한다.

공동 오라클·공개 조각·암호문을 보조정보로 포함하고 이 공동 모형과 호환되는
다중 정리 ZK를 가정한다. 시뮬레이터는 비공개 증인 없이
자료를 만드는 분석용 알고리즘으로, 모든 정규 문장에서 종료하는
PPT $\mathsf{SimProof}(td,x)$다. 참인 전체 이력의 CRS·증명
치환 이득을 $\epsilon_Z$로 둔다.
보호 비밀과 독립적으로 준비한 $td$는 생성기의 비공개 해시 질의
기록을 포함하지 않는다. 시뮬레이터·공개 후처리는 위 일곱 영역에
평가 질의로만 접근하며 내부 표를 읽거나 응답을 재프로그래밍하지 않는다.
증명계 전용 영역의 시뮬레이션 조건은 해당 증명계에 대해 정한다.
이 평가 질의는 감사 기밀성과 객체·식별자 분석의 해당 예산에 모두 포함한다.
PLONK 원문의 \S8은 다항식 무작위화와 Fiat--Shamir
비상호작용화의 영지식 구성을 설명한다~\cite{gabizon-plonk-2019}.
여기서는 이를 사용하는 증명계의 공동 관측 영지식 조건을 위와 같이 둔다.

\paragraph{정리 3의 증명.}
각 이력에서 먼저 참인 문장의 증명을 ZK 시뮬레이터로 바꾼다.
다음 감사 기밀성 게임에서 실제 벡터와 같은 길이의 영 벡터를
평문 쌍으로 제출하여 전체 암호문을 더미 평문의 암호문으로 바꾼다.
이 전체 치환의 이득은 $\epsilon_{\rm Aud}$ 이하다.
환원은 정직 이력의 평문·개방값을 생성하며, 도전 감사키·난수를
몰라도 시뮬레이터로 공개 입력의 증명을 만들 수 있다.
평문 길이와 전체 위치·배열 형상은 유지한다.
암호문의 바이트는 선택한 방식의 정직 암호화 분포를 따른다.

마지막으로 커미트먼트와 미래 식별자에 독립 균등 표지를 배정하고
공개 재사용·동일성을 보존한다.
Note 커미트먼트 입력에는 숨은 개방 난수 $\omega$가,
$nf$ 입력에는 소유 비밀 $s$가 필요하다.
같은 $s$를 재사용해도 서로 다른 $cm$는 다른 오라클 입력이다.
Voucher는 $\omega$를 공유하나 커미트먼트와 해결 비밀의 영역은
독립이다. 해결 비밀 $z$와 $(rv,z)$의 미래 식별자도 같은 공동
표에서 처리한다. 비밀을 맞히기 전에는 이 표와 독립 표지를
같은 분포로 결합할 수 있다.

외부·공개 후처리·시뮬레이터의 첫 숨은 입력 추측과 관련 충돌에
대해 객체 수 $n$, 소유자 수 $u$, 관련 객체 오라클 질의 수 $Q_{\rm id}$이면
$\epsilon_{\rm id}=O((n+u+Q_{\rm id})^2/2^{\min(\kappa,\lambda)})$다.
정직 생성기의 비공개 평가는 추측 질의로 세지 않는다.
더미 암호문은 객체 비밀·개방값과 독립인 설정·난수로 생성되며,
감사 암호화의 내부 질의는 객체 오라클의 숨은 입력을 포함하지 않는다.
따라서 이 단계의 숨은 입력 추측·충돌 상계는 기존 공동 표 분석과 같다.
그 밖의 루트·색인·Claim는 $L$과 공개 표지의 같은 함수다.
최종 분포는 같은 $L$, 같은 키·조각 분포와 독립 무작위 값으로
정해진다. 양쪽 변경의 삼각 부등식이 정리 3의 상계를 준다.

영지식 성질은 처음의 참인 이력에서 증명을 치환하는 단계에 적용한다.
이후 암호문·표지를 바꾸는 각 환원은 스스로 생성한 $td$의
total PPT 시뮬레이터를 공개 입력의 후처리로 사용한다. $\square$
