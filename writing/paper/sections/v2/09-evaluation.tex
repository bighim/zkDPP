\section{검증 및 실험 평가}
\label{sec:evaluation}

이 절에서는 먼저 평상시 거래의 처리 비용과 감사 자료를 추가할 때의
부담을 살펴본다. 이어서 문제가 있는 원료에서 파생된 기록을 찾아
사용을 막는 기능과 그 실행 비용을 평가한다. 마지막으로 소유권 이전 방식과
증명 구성에 따른 비용 차이를 비교한다.

\subsection{평가 방법}
\label{sec:evaluation-method}

실험에 사용한 증명 회로, 스마트 컨트랙트와 감사 프로그램의
소스코드를 공개하였다\footnote{\url{https://github.com/bighim/zkDPP}}.
각 평가에 사용한 코드 판본과 실행 자료는
해당 결과의 참고문헌에 연결하였다.

\ref{sec:proof-configuration}절의 구성에 따라 PLONK-KZG의
연구용 범용 설정 자료(SRS)와 회로별 증명·검증키를 사용했다.
고정 판본 \texttt{483f4a0}의 설정 코드는 암호학적 난수원으로
설정 비밀을 표본화하고, 모든 회로가 요구하는 최대 크기의 KZG SRS를
만든다. 이를 각 회로의 평가 영역에 맞는 Lagrange 형태로 변환하여
회로별 \texttt{plonk.Setup}에 전달한다~\cite{zkdpp-implementation-profile-2026}.
범용 SRS를 재사용하되 증명·검증키는 회로마다 준비한다.
평가는 설정 비밀이 공격자에게 알려지지 않고 등록 관계·검증키·공개 입력
순서가 유지된다는 신뢰 설정 전제를 사용한다.

라이브러리는 gnark v0.15.0과 gnark-crypto v0.20.1이다.
설정 검산과 거래 증명 생성에는 추가 옵션을 지정하지 않은
\texttt{plonk.Prove}를 사용했다~\cite{zkdpp-implementation-profile-2026}.
기본 호출에도 비공개 입력을 숨기기 위한 다항식 무작위화가 적용되며,
Fiat--Shamir 및 KZG 열기 증명의 결합 도전에는 SHA2-256을 사용한다.
\texttt{WithStatisticalZeroKnowledge}는 몫 다항식 조각의 추가
무작위화를 켜는 별도 옵션이다~\cite{gnark-plonk-options-015}.

표~\ref{tab:eval-env}는 성능 측정에 사용한 컴퓨터와
프로그램을 보여 준다. 증명 회로는 PLONK-KZG와 BLS12-381,
감사 자료 암호화는 Jubjub와 Poseidon2를 사용했고,
거래는 로컬 시험 원장인 Anvil에서 실행했다.
감사 암호화는 부록~\ref{app:acceptance}의 DH 기반 벡터 구성을
사용했다. hybrid ElGamal의 IND-CPA 문헌 결과를 적용하는 조건과
공개 확인 자료·일부 비밀 조각을 포함한 기밀성 논증은
부록~\ref{app:privacy-details}에서 설명한다.
거래 비용은 질량 $q$, 배분한 재활용 크레딧 $a$,
탄소 회계 값 $e$를 다루는 실행에서 얻었다.
성능 측정에는 실험용 회로를 사용했으며,
별도 설명이 없으면 Process는 입력 2개·출력 1개다.
입출력 수를 바꾸는 실험용 회로는 모든 출력을 양의 질량인
일반용으로 설정하였다~\cite{zkdpp-implementation-profile-2026}.
실험용 회로는 정수 단위의 탄소 배분값을 내림 계산하고 잔여를
한 출력에 배분한다.
정확히 나누어떨어지는 입력에서는 잔여가 없으므로
앞서 정의한 탄소 배분식과 같은 값을 낸다.
표~\ref{tab:eval-audit}--\ref{tab:eval-process}는
이 내림·잔여 배분 회로의 거래 비용을 제시한다.

거래 비용은 제약 수, gas, E2E로 구분했다.
제약 수는 증명 회로가 확인하는 계산 조건의 개수이고,
gas는 원장이 거래를 처리하는 데 쓰는 자원량이다.
E2E는 비공개 입력 준비부터 거래 성공 확인까지 걸린 시간이다.
표~\ref{tab:eval-events}의 거래별 비용은 준비 실행 1회 뒤
공식 측정 5회의 gas·E2E 중앙값을 사용했다.
감사 추가 비용, 추적·동결 시간과 전달 방식 비교도 준비 실행을 제외한
공식 5회의 중앙값이다.
표~\ref{tab:eval-process}의 입출력 수 비교는 별도 실험의
조건별 공식 1회 관측값을 사용했다.

추적·차단 기능은 위 성능 측정과 별도로, 실제 PLONK 증명을 생성하고
회로별 원장 검증기로 확인한 M1-HF 판본의 저장 실행 기록으로 검사했다.
이 거래 회로는 실제 입력의 부모 참조와 출력의 미래 소비 식별자를
계산하고, 이들로 구성한 평문을 암호화한 값이 공개 감사 암호문과
일치하도록 제약한다~\cite{zkdpp-m1hf-execution-2026}.
이 판본은 입력 3개를 일반용·폐기물 출력 하나씩으로 바꾸는
고정 Process와 객체를 시작점으로 한 추적·차단을 구현한다.
이 Process에서 일반용 출력의 질량은 양수이며,
폐기물 출력에는 질량 0을 허용한다~\cite{zkdpp-implementation-profile-2026}.
추적·동결 결과는 거래 영수증과 원장에 저장된 감사 자료로,
동결 상태의 소비 거부는 통합 시험 결과로 확인하였다~\cite{zkdpp-m1hf-execution-2026}.

감사 실행 비용 중 추적 시간은 기록 조회·복호화·연결 탐색을,
동결 시간은 대상별 상태 확인·거래 제출·최종 확인을 포함한다.
두 시간은 별도로 측정했다. 감사키 복원 시간은 공개 자료를
미리 확인한 뒤 조각 검증·결합·복원한 키의 대조에 걸린 계산 시간이며,
키 생성·위원과의 통신·감사 승인 대기는 제외했다.
기능 실행은 \texttt{164d51e}, 성능 자료와 집계 코드는
\texttt{483f4a0} 판본의 공개 저장소에 연결한다~\cite{
zkdpp-m1hf-execution-2026,zkdpp-evaluation-data-2026}.
표별 측정 조건은 이 절과 각 표에 명시하며, 거래별 공식 5회는
같은 장비·실험 실행 안의 반복이다. 공개 저장소에는 원시 실행 기록,
반복별 측정값과 집계 코드도 제공한다.

\subsection{거래 처리 비용}

추적에 필요한 감사 자료가 거래 비용을 얼마나 늘리는지 확인하기 위해,
같은 조건에서 감사 자료를 넣은 거래와 뺀 거래를 비교했다
(표~\ref{tab:eval-audit}). 감사 자료를 넣으면 제약 수는
31.70--202.93\%, gas는 9.69--54.67\% 증가했다.
Transfer의 추가 비용 356,146 gas 중 감사 기록의 원장 저장 연산
(SSTORE)은 324,100 gas로, 추가 비용의 91.00\%를 차지했다.
나머지는 증명 검증 증가분 4,585 gas와 조회·입력 전달 등
기타 증가분 27,461 gas다~\cite{zkdpp-evaluation-data-2026}.

\subsection{추적과 차단}
\label{sec:eval-trace}

거래에서 생성된 감사 자료로 선행 원료와 후속 기록을 찾을 수 있는지
확인하기 위해, 실제 증명을 검증하는 원장에 등록·이전·가공·발급을
포함한 거래 이력을 구성하였다. 저장된 감사 자료를 복호화하여
원료에서 후속 기록을 추적한 결과, 발급된 Claim과 종료된 경로,
아직 소비되지 않은 Note를 찾았다. 발급된 Claim에서 선행 기록을
추적했을 때는 해당 이력의 원료 Entry 네 개에 도달했다~\cite{
zkdpp-m1hf-execution-2026}.

추적한 대상을 원장에서 차단할 수 있는지는 별도의 분기 이력으로
확인하였다. 원료 $A$를 $B,C$로 나누고 $B$를 다시 $D,E$로 나눈 뒤,
$A$에서 후속 추적을 수행하여 미소비 대상 $C,D,E$를 찾았다.
세 대상에 각각 동결 거래를 제출하고, 공통 확정 시점에서 모두
미소비·동결 상태임을 확인하여 전체 대상의 차단 완료를 판정하였다~\cite{
zkdpp-m1hf-execution-2026}.

동결된 기록의 사용이 거부되는지는 별도의 원장 통합 시험으로
확인하였다. 기존 시험 결과에 따르면 Note를 동결한 상태에서는
Transfer가 거부되었고, 동결을 해제한 뒤 허용 기한 안에서 같은
거래가 승인되었다. Voucher를 동결한 상태에서 Recall을 제출한
경우에도 거래가 거부되고 미소비 상태가 유지되었다. 이 결과는
검사한 두 소비 경로에서 동결이 기록의 다음 사용을 제한함을 보여준다~\cite{
zkdpp-m1hf-execution-2026}.

이러한 감사를 시작하기 위한 준비 비용으로 감사키 복원 시간을
측정했다(표~\ref{tab:eval-key}). 전체 위원 수를 10명으로 고정하고
복원에 필요한 최소 조각 수를 2--10개로 바꾸어,
각 조건에서 해당 수의 조각을 사용했다.
컴퓨터 안에서 수행한 복원 계산은 평균 0.188--0.737\,ms로,
측정한 모든 조건에서 1\,ms 미만이었다~\cite{zkdpp-evaluation-data-2026}.
\input{tables/evaluation/key}

감사 규모가 커질 때의 실행 비용은 방문 기록 수와 동결 대상 수를
각각 늘려 확인했다(표~\ref{tab:eval-trace}). 방문 기록을 100개에서
1,000개로 늘리면 후속 추적은 0.681초에서 9.760초로 증가했다.
별도로 측정한 동결 대상이 100개에서 1,000개로 늘면,
동결 시간은 2.448초에서 60.540초로 증가했다.
이 구성에서는 대상마다 동결 거래를 한 번씩 제출한다.
따라서 감사 규모에 따른 부담을 평가할 때는 기록 탐색뿐 아니라
대상별 원장 차단에 걸리는 시간도 함께 고려해야 한다.

\subsection{설계 선택과 기존 연구의 비교}

표~\ref{tab:eval-transfer}는 한 번에 끝나는 직접 전달과
Transfer 뒤에 Proceed 또는 Recall을 수행하는 두 단계 이전을 비교한다.
두 단계 이전에서는 인수 전 허용된 기한 안에 회수할 수 있다.
송신자는 인수 뒤 수신자 Note의 소비 식별자를
수신자의 소유 비밀 없이 직접 계산할 수 없다.
반면 비교용 SharedSecret 직접 전달에서는 송신자가 그
소비 식별자를 계산할 수 있다.
Transfer와 Proceed의 5,361,496 gas는 두 거래의 값을
더한 수치이며, 비교에는 감사 자료의 유무와 거래 수가 다른
각 전달 경로의 전체 비용을 사용했다.
\input{tables/evaluation/transfer}

거래 조건을 한 증명으로 묶는 선택의 제출·검증 비용을 살펴보기 위해, 앞의
PLONK-KZG 측정과 별도로 BN254/Groth16·Poseidon2
예비 실험을 수행했다.
Sahai 등의 두 입력 병합 거래에서 사용한 증명 분해
방식~\cite{sahai-supply-chain-2020}을 참고해
검증 조건을 각각 따로 증명하는 개별 증명 구성과
이 조건들을 한 회로에 묶어 증명하는 단일 증명 구성을 비교했다.
이 예비 실험의 개별 증명 구성은 증명 6개를,
단일 증명 구성은 증명 1개를 사용했다.
증명 크기의 합은 각각 1,536바이트와
256바이트로 83.33\% 줄었고,
로컬 순차 검증 시간의 중앙값은 각각 6.289\,ms와
1.056\,ms였다(준비 실행 1회 뒤 각 5회 측정).
이 실험에서 단일 증명 구성은 제출할 증명 수를 줄여,
전송·보관할 증명 데이터와 순차 검증에 걸리는 시간을 줄였다.
개별 증명 구성의 예비 구현에는 증명들이 같은 거래에 속하는지
확인하는 검사가 빠져 있고, 머클 트리의 잎에 넣는 값도 원 논문과 다르다.
따라서 관측한 감소는 이 예비 구성에서 제출한 증명 자체의 크기와
반복 검증 비용에 한정된다.

이 예비 비교에서 단일 증명 구성은 제출 데이터와 반복 검증 부담을 줄였다.
감사를 위한 연결 정보 저장은 평상시 거래에 비용을 더하며,
측정한 Transfer의 추가 gas는 대부분 감사 기록 저장에서 발생했다.
두 단계 이전에는 두 거래의 비용이 든다. 이 절차로 인수 전 회수를
허용하면서, 인수 뒤의 소비 식별자는 송신자가 직접 계산할 수 없게 한다.
따라서 증명 통합의 비용 효과와 감사·이전 기능을 제공하는 비용은
서로 다른 항목으로 해석할 수 있다.
