## 1. 무엇을 증명하는가

| 성질 | 핵심 질문 | 포함하는 보장 |
|---|---|---|
| Correctness | 필요한 조건이 갖춰졌을 때 정직한 실행이 의도한 결과를 내는가? | 유효 전이 수락·상태 갱신, 공개 DPP 검증, 승인 후 정확한 선행·후속 추적, 경합과 처리 장애가 없는 동결 완료 |
| Soundness | 잘못된 거래나 결과를 정당한 것으로 받아들이게 할 수 있는가? | 실제 생성 값에 대한 전이·감사 결합, 잘못된 추적 성공 방지, 거짓 전체 완료 방지, 차단 유지 중 후속 소비 거부 |
| Privacy | 허용된 공개 정보 외의 비밀 값과 연결을 알아낼 수 있는가? | 공개 확인 자료·정적 K개 미만 조각 아래 감사 벡터 기밀성과 제한된 수동 외부 관찰자의 원장 구별 불가능성 |

정리는 위 세 개다. 추적과 차단은 Correctness와 Soundness가 적용되는 절차이며 별도의 최상위 보안 성질로 세지 않는다. 정상 상황에서 성공하는 보장과 오류·경합 상황에서 거짓 성공을 내지 않는 보장을 구분한다. Privacy는 참여자 비밀·개방값 공개 및 능동 질의가 없는 제5절의 감사 기밀성·공동 객체 무작위 오라클·영지식 프로필에 한정한다.

## 2. 모델·공개 관계·가정

보안 매개변수는 λ다. 모든 공격자, 실행 길이, 객체·증명·오라클 질의 수는 λ의 다항식으로 제한한다. `negl(λ)`는 무시 가능한 함수다. 기밀성의 advantage는 두 실험에서 공격자가 1을 출력할 확률의 절댓값 차이로 정의한다(추측 성공률에서 1/2를 뺀 값과 계수가 다르다).

배포는 규범 §8의 전체 전이 관계 `R_kind,policy(x,w)`를 고정한다. `x`는 이벤트 종류, 등록 경로의 정책·scope, membership roots, typed input spend identifiers, 순서 있는 전체 output references, 감사 암호문·배열 형상 및 기타 공개 필드를 포함한다. `w`는 실제 입출력 개방값, 소유 비밀, 경로, 정책 증인과 한 벡터의 암호화 난수를 포함한다. 관계는 규범의 정수 범위·중복·타입·고정 키·전체 암호문과 공개 statement의 대응 검사까지 포함한다. `ValidRuntime(S,x)`는 수락/집행 직전 상태 S의 권한, registry, accepted roots, 미소비·Active, deadline, fresh outputs 등을 검사한다. 원장은 관계에 고정된 검증키만 선택하고, 검증·runtime 검사·상태와 색인 갱신을 원자적으로 수행한다.

**신뢰 경계.** 최종 확정된 원장의 이력·registry·권한 판정·현재 상태 집행은 정확하다. Auditor=Status Authority는 신뢰된다. 외부 인증된 절차로 유효한 `SK_B`를 제공받으며, 악의적 키 전달 서비스에 대한 보안은 여기서 주장하지 않는다. 현실 입력의 진실성과 승인 정책의 현실적 적절성도 가정 밖의 별도 문제다. 공격자는 일반 참여자를 제어하고 전이를 적응적으로 제출할 수 있지만, 신뢰 기관의 권한 판정을 마음대로 바꾸는 오라클을 받지 않는다.

Soundness와 그 추적·차단 보조논증의 암호 계약은 다음과 같다.

1. **X: 적응적 다중 증명 지식 건전성.** 정직한 증명 생성 질의를 포함하는 다항 길이 실행에서 공격자가 제출해 수락된 새로운 `(x,π)`마다 `R(x,w)=1`인 증인을 함께 확보하는 공동 PPT 추출기가 있다. 추출은 전체 transcript에서 수행한 뒤 수락 순서로 정렬해도 된다. 정직한 증명의 동일 재전송에는 원래 증인을 사용한다. 단일 정리 soundness나 단일 증명의 지식 추출만으로 이 동시 실행 계약을 추정하지 않는다. 보조 입력·여러 등록 관계·정직 proof oracle을 포함한 계약의 실패 상계를 `ε_X`라 한다.
2. **C: 정규 인코딩과 결합성.** 타입, 필드 경계, 정수 영역을 보존한다. PPT 실행에서 하나의 Note/Voucher 참조에 서로 다른 두 전체 개방값을 제시하는 확률은 `ε_C` 이하이다. 이는 모든 수학적 개방값의 유일성이 아니라 계산적 결합성이다.
3. **M: 포함 관계의 건전성.** 수락된 루트의 실제 등록 leaf가 아닌 객체의 유효 포함 증인을 만들 확률은 `ε_M` 이하이다. 과거 accepted root의 사용 자체는 허용하지만 소비·상태는 현재 값으로 별도 검사한다.
4. **H: 정규 해시 입력의 충돌 저항성.** `OwnerKey(s)=H_Owner(s)`와 objectKey, typed spend identifier, 문서·Claim 결합에서 서로 다른 관련 정규 입력의 충돌을 찾는 확률을 합쳐 `ε_H`로 상계한다. 여기에는 공동 추출 실험이 생성·소비 증인에서 확보한 서로 다른 소유 비밀 s,s'에 대해 `H_Owner(s)=H_Owner(s')`인 사건도 포함한다. Note와 Voucher의 종류를 혼동하지 않는다. 예산 전체에 대한 상계이며 질의 1회당 확률을 근거 없이 대입하지 않는다.
5. **E: 적대적 난수까지 포함한 복호화 정확성.** 생성된 올바른 키쌍, 모든 허용 평문 벡터·난수 η에 대해 `Dec(SK_B, Enc(PK_B,M;η))=M`. 완전 정확성이면 실패 확률은 0이다. 이를 완화하려면 PPT가 **직접 고른** 유효 난수에서 복호화 실패를 만드는 확률 `ε_E`가 무시 가능해야 한다. 정직한 난수 평균에서만 정확하다는 조건은 불충분하다.

가정 E가 필요한 이유는 prover가 η를 witness로 고르기 때문이다. 예를 들어 η=0일 때만 오복호화하는 방식은 정직한 κ비트 난수에서 실패가 2^−κ이어도, 악의적 prover가 항상 η=0을 골라 accepted record를 오복호화시킬 수 있다. Audit 관계가 난수의 허용 영역을 검사하거나 방식 자체가 그 영역에서 완전 정확해야 한다.

현행 규범의 벡터 관계에서는 유효 키쌍과 허용 η에 대해
`SK_B * R1 = SK_B * (ηG) = ηPK_B`다. 생성자와 감사자가 동일한 대칭키 `k_sym` 및
전체 위치 j의 마스크를 계산하므로, 유한체에서 마스크를 빼면 각 M[j]를
그대로 얻는다. 이 대수적 정확성과 실제 인코딩·회로의 적합성, 그리고
암호문의 기밀성은 서로 다른 확인 항목이다.

**추출 실험의 분포와 권한.** X는 공개 transcript만 받아 누구나 witness를 복구하는 알고리즘이 아니다. 증명 설정의 비공개 extraction trapdoor 또는 명시된 공격자 black-box/rewinding 접근을 가진 공동 PPT 실험이 `(τ,Witnesses)`를 생성한다. 공개 τ의 marginal은 실제 Setup/정직 오라클/Submit 실행과 동일해야 하며, 통계적 거리 δ_X를 허용하면 그 항도 ε_X에 포함한다. 추출 권한은 수동 관찰자에게 주지 않는다. 보조정보는 독립 C/M/H/E challenge 비밀을 주지 않고 reduction이 생성할 수 있어야 하며, 이 공동 실험의 PPT가 얻은 witness 쌍에도 각 primitive 가정이 적용되어야 한다. 구체 증명계가 이 계약을 충족하는지는 별도 의무다. 아래 주석 게임의 확률은 이 명시적 실제-marginal 공동 실험으로 정의한다.

편의상 `ε_B=ε_X+ε_C+ε_M+ε_H+ε_E`라 둔다. 각 항은 해당 실행 예산에 대한 환원 공격자의 성공 상계다. 구체 방식과 예산이 없으므로 숫자나 보안 비트를 부여하지 않는다.

## 3. Correctness

**정의.** 정직한 참여자·감사자와 정확한 원장이 규범 알고리즘을 실행할 때, 해당 호출에 필요한 유효성·가용성·상태 안정 조건이 갖춰졌다면 의도한 정상 결과를 내야 한다. 여기서 정상 조건은 다음과 같다.

1. **전이·공개 검증:** 호출 시 전체 관계와 runtime 조건을 만족하는 명령·정직 증인이 있고, 출력이 신규이며 tree capacity가 충분하다. 증명 생성 뒤 집행 전까지 권한·정책·소비·상태·기한 조건이 유효하다. 공개 검증에는 발급이 포함된 인증 prefix와 그 발급에 일치하는 정규 DPP 세 필드·policy·nonce·Claim을 제시한다.
2. **추적:** 정직하게 생성된 유효 이력, 유효한 시작점·확정 H_t와 외부에서 확보한 유효 AuditKey가 있다. 필요한 유한 기록과 인증 조회가 가용하며 정상 응답이 종료한다. 목표 그래프는 제4.2절의 생성·소비 관계로 독립 정의한다.
3. **동결:** 해당 시작점의 차단 승인이 있고 위 추적 조건이 충족된다. T=∅이면 추가 동결 조건 없이 빈 대상 분기를 따른다. T≠∅인 경우에만 다음 조건을 요구한다. 전체 T는 H_t부터 공통 결과 확인 H_r까지 소비되지 않으며, 이미 차단된 대상은 차단 상태를 유지한다. Active 대상의 합법적 Freeze가 규정된 유한 시도·확인 한도 안에 수락·확정되고 해제되지 않는다. 필요한 상태 조회와 사용한 관찰·제출 결과를 모두 반영하는 같은 chain의 H_r을 그 한도 안에 확보한다. 단순히 언젠가 응답한다는 조건은 아니다.

각 호출의 위 전제가 성립하는데도 기대 결과를 내지 못하는 사건을 Fail_corr로 정의한다. 전제가 깨진 뒤 정상 거부하거나 INCOMPLETE를 반환하는 실행은 여기에 포함하지 않는다. 정직 생성 과정에 proof 생성이 Q회 이하이고 1회 완전성 실패 상계가 ε_comp라고 하자.

**정리 1 (Correctness).** 위 모델과 복호화 계약 E 및 관련 해시 충돌 계약 H 아래, 전체 실행의 정상 조건 충족 호출에서 정확성 위반이 생길 확률은

`Pr[Fail_corr] ≤ Q·ε_comp + ε_E + ε_H`

이다. E가 완전 정확하면 ε_E=0이다. ε_H는 정직 생성에서도 가능한 서로 다른 객체의 typed 소비 식별자 충돌 등을 포함하는 전체 실행 상계다. 신규 output reference 조건만으로 미래 소비 식별자 충돌까지 배제하지 않는다. 이는 정상 조건과 위반이 함께 발생하는 사건의 상계이며, 희귀한 정상 조건 사건에 조건을 건 확률 상계를 새로 주장하지 않는다. 구체적으로 전이는 수락되어 규범 Apply를 수행하고, 일치하는 공개 DPP는 valid로 판정되며, 추적은 정확한 선행·후속 그래프·경계·종단을 반환한다. 동결의 정상 조건이 갖춰지면 T≠∅일 때 COMPLETE_AT_CHECKPOINT, T=∅일 때 NO_LIVE_TARGETS를 반환한다.

**증명.** 정직 증인은 전체 관계를 만족하므로 proof 완전성 실패가 없으면 Verify를 통과한다. 유효 runtime·신규 출력·capacity와 안정 조건으로 나머지 검사도 통과하며, 원자적 Apply가 정해진 상태와 색인을 갱신한다. 동일 encoding과 실제 등록 Claim을 사용한 DPP 검증은 같은 문서 해시·policy·nonce 결합을 확인한다. 정직 생성 증인을 기준으로 실제 부모와 미래 식별자가 암호화되므로 E의 실패 밖에서 정확히 복호화된다. 생성·소비가 같은 객체의 같은 비밀과 opening을 사용하므로 typed 식별자도 일치한다.

관련 해시 충돌이 없으면 서로 다른 객체의 typed 소비 식별자는 구별된다. 그 뒤 추적은 제4.2절의 seed에서 출발해 실제 producer·consumer를 따라간다. 제4.3절의 경로 귀납으로 정점·간선·경계·종단이 정확하며, 유한 그래프·방문 처리와 종료하는 조회로 정상 종료한다. 고정 H_t의 추적에는 그 이후 원장 전체의 무경합을 요구하지 않는다. 이 귀납 자체에는 악의적 증인의 추출이 필요하지 않다. 정직하지 않게 생성된 수락 이력으로의 확장은 정리 2에서 다룬다.

동결에서는 정확한 전체 T를 보존하고 각 Active 대상을 처리한다. T가 비면 규범의 빈 대상 분기를 따른다. 그 밖에서는 가정한 처리·확정·상태 유지로 같은 H_r에서 모든 대상이 미소비·차단이고, 결과 목록과 제출 처리도 모두 정산된다. 따라서 제13.4절의 완료 검사가 통과한다. 이 논증은 완료 여부를 전제로 놓지 않고 그것을 실행 조건에서 도출한다. 나머지 실패는 proof 완전성·E 실패·관련 해시 충돌의 합집합에 포함되므로 상계가 따른다. □

정확한 trace가 나왔다는 이유만으로 동결 완료까지 보장하지 않는다. 데이터·키 부재, 소비 경합, 동결 해제 또는 확인 한도 내 확정 실패는 위 정상 조건 밖이다. 이때 성공을 강제하는 대신 오류와 INCOMPLETE를 정확히 보고해야 한다는 보장은 Soundness에 포함된다.

## 4. Soundness

### 4.1 실제 전이와 감사 결합

`Exp_transition(A,λ)`의 challenger는 정상 Setup 후 다음을 수행한다.

1. `HonestEvent(command)`는 규범에 유효한 정직 전이와 증명을 생성한다. `Submit(x,π)`는 공격자가 임의로 제출한 전이를 실제 Verify와 `ValidRuntime`으로 처리한다. 실패는 원장을 바꾸지 않는다. 두 질의와 `CheckDPP(H_v,DPP,p,h,nonce)`를 적응적으로 섞을 수 있다. CheckDPP는 A가 고른 확정 prefix H_v의 인증된 조회로 규범 VerifyDPPClaim을 실행하고 valid이면 생성 목록의 Issue tuple/입력 d와 비교한다. H_v가 발급 이후라는 전제는 주지 않고 실제 등록 조회가 이를 판정한다.
2. **분석용 주석 원장**을 유지한다. 정직 생성에는 실제 증인을, 공격자의 수락에는 X의 추출 증인을 붙인다. 처음 생성된 객체 r에 대해 `C[r]=(Open[r], Note의 생성 ownerSecret, typed 미래 sid, birth aid)`를 보존한다. `Inv[(type,sid)]=r`를 생성 때 고정하고, `ActualInputs(e)`는 e의 순서 있는 공개 typed sid들을 이 역대응에 적용한 목록이다. Claim은 sid를 갖지 않으며 최초 Issue의 d/p/nonce/h를 별도 보존한다. 역대응 충돌은 BadID, 없는 입력 대응은 의미 위반이다. 이는 감사자에게 추가 정보를 주는 구현 기능이 아니다.
3. 승인된 실제 그래프는 처음 생성된 참조와 이 주석 개방값으로 정의한다. 입력을 이후 witness가 주장하는 값으로 다시 정의하지 않는다. 별도 의미 검사기는 실제 이전 `Open[r]`와 현재 상태에 대해 규범 §8–10을 평가한다.
4. 다음 사건 중 하나가 생기면 공격자가 성공한다: 수락 입력이 이전에 생성되지 않았거나 생성 때와 다른 개방값을 사용함; 같은 객체의 반복 계상·소비; 실제 생성 개방값에 대해 소유 비밀·회계·정책·권한 관계가 거짓인 수락; 감사 복호화가 실제 부모 또는 생성/소비 식별자와 다름; current status/deadline/registry에 반하는 수락; 인증된 prefix에서 미등록 Claim이 유효로 판정되거나 공개 DPP 세 필드의 해시·정책·nonce가 해당 Issue의 입력 Note에 결합된 d 및 Claim tuple과 다른데 유효로 판정됨. 과거 Claim에 현재 policy.enabled나 새 status 조건을 추가하지 않는다.

관계가 “어떤 witness를 가진다”는 것만을 성공/실패 정의로 사용하지 않는다. 해당 witness가 **먼저 수락된 객체의 생성 값** 및 순차 상태와 일치하는지가 핵심이다. 추출 실패는 분석상 BadX로 잡고 결과 실패 상계에 포함한다. 모호하거나 추출되지 않은 카탈로그/그래프는 ⊥로 정의한다. 게임은 Bad 발생 시 1로 종료하고 그 밖에서만 의미 위반을 비교하므로 모든 실행에서 정의된다. 이 보수적 분석 게임의 성공이 현실에서 관측 가능한 공격 성공과 동일하다는 뜻은 아니다.

**전이 보조논증.** 제2절의 계약 아래 `Pr[Exp_transition(A,λ)=1]≤ε_B`이다. 이때 소유권 보장은 관계에 맞는 비밀을 알고 있다는 의미다. 관계가 허용하는 소유 비밀의 누출 자체를 막거나 현실의 신원·동의를 추가로 인증하는 정리는 아니다.

**증명.** 추출 실패, 같은 참조의 서로 다른 생성/소비 개방값, 거짓 포함 증인, 관련 해시 충돌, 허용 난수의 오복호화가 처음 발생하는 사건들의 합집합을 Bad로 둔다. X/C/M/H/E로 `Pr[Bad]≤ε_B`다. `¬Bad`에서 수락 순서에 대한 귀납을 적용한다.

초기 원장은 빈 상태다. 어떤 수락 입력의 membership 증인은 이전 accepted root의 실제 leaf를 가리킨다. 불변 producer index와 fresh output 규칙으로 생성 이벤트는 하나이며 먼저 수락되어 있다. 생성·소비 개방값이 다르면 C에 대한 명시적 충돌 쌍이므로 `¬Bad`에서는 같다. 따라서 추출 witness의 회계·타입·소유 비밀·정책 검사를 생성 당시 실제 값에 적용할 수 있다. 모든 합·곱은 규범의 정수/no-wrap 검사를 포함하므로 유한체 등식만 만족하는 초과값을 허용하지 않는다.

Note는 생성 때와 소비 때 같은 `cm,owner`를 갖는다. 생성 witness의 소유 비밀을 s, 소비 witness의 비밀을 s'라 하면 두 소유권 관계가 `H_Owner(s)=owner=H_Owner(s')`를 준다. s≠s'이면 공동 PPT 추출 실험에서 확보한 두 정규 입력은 소유자 해시의 명시적 충돌 쌍이며 H의 전체 실행 상계 `ε_H`에 포함된다. 따라서 `¬Bad`에서는 s=s'이고 결정적 `nf=H_NF(cm,s)`도 같다. Voucher는 전체 opening에 결합된 같은 난수 ω에서 `s_res=H_res(ω)`와 `rvnf=H_RVNF(rv,s_res)`를 계산하므로 Proceed와 Recall도 동일하다. 서로 다른 같은 타입의 객체가 같은 소비 식별자를 쓰면 그 해시 입력에는 서로 다른 참조가 있어 H에 반한다. 타입이 다르면 typed table에서 구별한다. Claim에는 소비 식별자가 없다.

입력 중복은 관계가 거부하고, 같은 객체의 후속 재소비는 위 식별자 불변성과 현재 spent table 때문에 거부된다. atomic update는 두 경합 소비의 동시 수락을 배제한다. 현재 Frozen/Revoked 상태와 기한·권한·정책 위반도 runtime 검사에서 거부된다. 과거 membership root를 쓸 수 있다는 사실은 이 현재 검사를 우회하지 않는다.

암호화 관계는 방금 확정한 실제 부모의 원시 참조와 출력의 실제 미래 식별자를 순서대로 이어 붙인 한 벡터 M을 사용한다. 고정 공개키와 동일 공개 statement의 R1·두 배열·정규 순서 및 E에 의해 전체 복호화도 그 M이다. 각 값의 타입과 부모/출력 위치는 선택한 Event 형상 및 공개 outputRefs에서 복원한다. 거래 문맥을 암호 해시에 별도로 넣는다고 가정하지 않는다. 악의적 prover가 다른 암호문을 골라 같은 공개 관계를 만족시켰더라도, 그 암호문이 관계의 `Enc(M;η)`와 같으면 E가 동일 평문을 반환한다. 별도의 암호문 무결성 가정을 암묵적으로 사용하지 않는다.

Issue는 실제 Note를 소비해 등록된 Claim을 만든다. 공개 검증은 인증된 등록 이력과 policy/nonce/handle을 확인한다. 공개 세 필드에서 계산한 d 또는 policy/nonce가 Issue의 tuple과 다른데 같은 h로 검증되면 H의 충돌이다. Note는 d만 보관하므로, 존재가 보장되지 않은 '원래 전체 문서'까지 추출했다고 주장하지 않는다. 별도로 원래 세 필드의 정규 자료가 주어지면 문서 해시의 충돌 저항성으로 그 자료와의 일치도 얻을 수 있다. 이는 문서 전체, 물리 제품 또는 policy의 현실 적합성을 증명하지 않는다. 따라서 `¬Bad`에서 게임의 성공 사건이 없고 전이 보조논증이 따른다. □

### 4.2 실제 그래프의 정의

제4.1절의 `¬Bad`에서 accepted prefix `H_t`로 이분 DAG `D_t`를 만든다. `ActualInputs(e)`의 객체→실제 소비 이벤트, 이벤트→전체 출력 객체의 간선을 갖는다. 생성이 소비보다 앞서고 객체 생성이 유일하므로 DAG다. 아래 그래프는 암호문이나 audit algorithm의 반환값을 읽어 정의하지 않는다.

**후속 목표 `F_t(start)`.** 객체 시작의 seed는 그 객체 하나, record 시작의 seed는 그 record의 모든 출력이다. 이 seed 객체들의 최소 forward closure를 취한다: 포함된 Note/Voucher가 소비되었으면 실제 consumer와 해당 입력 간선을 포함하고 consumer의 전체 출력과 그 간선을 포함한다. Claim과 출력 없는 Exit는 종단이다. 다른 부모의 선행 방향으로 확장하지 않는다. seed producer 자체와 seed producer→output 간선은 seed라는 이유만으로 넣지 않는다. 따라서 Exit record 시작의 후속 그래프는 빈 그래프다. 도달한 미소비 Note/Voucher가 typed frontier다.

**선행 목표 `B_t(start)`.** 객체 시작이면 그 객체, producer와 producer→객체 간선으로 시작한다. record 시작이면 그 record와 **모든 직접 출력 및 그 출력 간선**으로 시작한다. 이어 포함된 이벤트의 모든 실제 입력과 입력 간선을 넣고 각 입력의 producer 및 producer→입력 간선을 거슬러 올라가는 최소 closure다. 재귀 중 읽은 producer의 다른 sibling output은 추가하지 않는다. Entry 이벤트 집합도 반환한다. 따라서 record 시작의 선행 결과는 단순히 그 event로 역방향 도달 가능한 정점 집합과 다르다.

두 정의는 규범 §11–12의 서로 다른 시작점 의미를 보존한다. 특히 `Entry e→a`만 있는 유효 이력에서 `B_t(e)`는 e,a와 출력 간선을 포함하고, `F_t(e)`는 a만 포함한다. sibling 구분은 `Entry e_0→u; Split e: u→{a,b}`에서 볼 수 있다. `B_t(e)`에는 두 출력과 e_0,u,e가 모두 들어가지만 `B_t(a)`에는 b가 없다.

### 4.3 잘못된 추적 성공의 배제

`Exp_trace(A)`는 제4.1절의 적응적 수락 이력 뒤 A가 기존 시작점, 방향 및 확정 prefix를 선택하게 한다. 감사자는 그 prefix를 고정하고 외부에서 유효한 AuditKey를 받는다. 읽기 어댑터는 해당 prefix의 인증된 실제 값 또는 오류만 줄 수 있다. 자료를 숨겨 실패시키는 것은 허용하지만 잘못된 값·거짓 부재를 인증된 값으로 주는 것은 신뢰 가정 위반이다. Bad에서는 게임이 1을 반환한다. 그 밖에서만 성공 반환을 제4.2절의 목표 그래프/경계/종단과 비교해 다르면 1, 오류 또는 정확한 결과면 0을 반환한다.

**추적 보조논증.** 위 게임의 잘못된 성공 확률은 `ε_B` 이하이다. `¬Bad`에서 필요한 유한 기록과 키가 가용하고 정상 조회가 종료하면 감사도 정상 종료해 정확한 값을 반환한다. 가용성이 없으면 오류 반환·중단을 허용하며, 없는 자료를 빈 그래프로 취급하는 성공은 허용하지 않는다.

**증명.** `¬Bad`에서 선행 감사의 부모 복호화는 실제 입력 목록이다. 최초 seed 간선은 `B_t`의 정의와 같고, 한 이벤트 확장은 그 실제 부모와 그들의 producer를 추가한다. 탐색 길이 귀납으로 추가 간선은 모두 목표에 속한다. 반대로 목표의 각 부모 경로는 해당 이벤트를 처음 확장할 때 추가되므로 누락되지 않는다. 이미 확장한 producer라도 새로 도달한 output 간선을 visited 검사 전에 추가하므로 분기 후 재합류에서 간선을 잃지 않는다.

후속 감사의 seed는 `F_t`의 정의와 같다. 전이 보조논증으로 복호화한 미래 식별자는 실제 소비 식별자다. 인증된 spent=0은 정확히 미소비를 뜻하고, 양수 값은 불변 index의 유일 consumer다. 한 번 도달한 consumer는 모든 출력을 전개하며 재방문 입력 간선은 보존한다. 따라서 추가되는 정점·간선·typed frontier/Claim/Exit 집합이 모두 목표와 같고, 목표의 각 유한 경로가 귀납적으로 처리된다. 유한 DAG에서 방문 표시는 객체/이벤트를 유한 번 처리하게 한다. 조회 실패 시 require가 실패하고 성공 결과를 반환하지 않는다. Bad의 확률 상계가 추적 보조논증에 전달된다. □

### 4.4 전체 경계 차단과 완료 보고

**경계 보조논증.** `T`를 정확한 `F_t(start)`의 전체 typed frontier 식별자 집합으로 고정한다. 공통 확정 시점 `H_r≥H_t`에서 `T≠∅`이고 모든 t가 미소비이며 Frozen/Revoked라고 하자. 그러면 `(H_t,H_r]` 사이에 그 후속 경로를 새로 소비한 이벤트는 없다. 이후에도 T의 모든 객체가 차단된 동안 그 경로의 추가 소비는 수락되지 않는다. 이 결정적 함의는 `¬Bad`인 전체 실행에서 성립한다. 다음 출력 게임의 비조건부 상계와 구분한다.

**증명.** 반례 중 `H_t` 이후 최초로 수락된 후속 소비를 고르면, 그 입력 중 후속 경로에 속하는 하나는 `H_t`에 이미 존재하면서 미소비였어야 한다. 아니면 더 이른 후속 생성/소비가 필요해 최초 선택과 모순이다. 따라서 그 입력은 T다. 소비 index가 불변이므로 `H_r`에 다시 미소비일 수 없어서 전반부가 따른다. `H_r` 이후 최초의 추가 소비 역시 T의 입력을 필요로 하지만 현재 상태 검사가 이를 거부한다. 다른 정상 입력과의 Merge/Process도 차단된 한 입력의 검사를 생략할 수 없다. □

**완료 출력 게임.** 전체 다항 실행 예산에 감사 이후의 추가 이벤트까지 포함한다. A는 일반 이벤트, 허용된 합법적 상태 변경의 스케줄과 자료 제공/오류를 선택한다. 신뢰된 SA는 규범 AuditAndFreeze를 직접 실행하고 추적에서 얻은 전체 T를 보존한다. H_t/H_r은 같은 확정 chain에 속하며 H_r은 사용한 관찰·영수증을 반영하는 적법한 공통 시점이어야 한다. 공격자가 COMPLETE 문자열을 임의로 제출하는 게임이 아니다. Bad에서는 1을 반환하고, 그 밖에서는 SA가 COMPLETE를 반환했는데 규범의 완료 술어가 거짓이거나 위 유지 구간 차단 함의가 깨지면 1을 반환한다. 따라서

`Pr[SA가 COMPLETE를 반환 ∧ (완료 술어가 거짓 ∨ 주장한 구간의 후속 소비 발생)] ≤ ε_B`.

이는 공동 사건의 **비조건부 상계**다. `Pr[위반 | COMPLETE]≤ε_B`라고 주장하지 않는다. `¬Bad`에서는 추적 보조논증으로 정확한 T를 얻고 신뢰된 SA와 인증 조회가 완료 술어를 확인하므로 경계 보조논증의 결정적 귀납이 위반을 배제한다. 같은 Bad를 독립 사건처럼 중복 계산하지 않는다.

`COMPLETE_AT_CHECKPOINT`는 여기에 전체 T와 결과의 정확한 대응, 불명확한 제출의 부재, 유효한 공통 시점 선택까지 요구한다. T가 빈 결과는 `NO_LIVE_TARGETS`이고 부분 동결·경합은 `INCOMPLETE`다. T를 줄이거나 소비된 대상을 버려 완료로 바꿀 수 없다. 이 경계 조건은 모든 대응 방식의 필요조건, 동결 해제 뒤 영구 차단, 이미 발급한 Claim 취소 또는 물리 회수 정리가 아니다.

### 4.5 통합 게임과 증명

**정의와 게임.** Soundness는 위 세 실패를 한 실행에서 배제한다. `Exp_sound(A,λ)`는 제4.1절의 HonestEvent·Submit·CheckDPP를 제공하고, 공격자가 그 수락 이력의 확정 prefix·유효 시작점·방향을 골라 제4.3절의 추적을 실행하게 한다. 후속 추적에 대해 차단 승인이 있는 경우에는 제4.4절처럼 신뢰된 SA가 AuditAndFreeze를 실행할 수 있다. 공격자는 허용된 전이·합법적 상태 변경·조회 오류를 스케줄하며 감사 이후 전이도 전체 다항 예산에 포함한다. 새로운 키 공개·복호화 서비스나 신뢰 기관의 임의 권한 변경 질의를 추가하지 않는다.

하나의 생성 목록과 전체 실행의 Bad를 사용한다. Bad이면 게임은 1로 종료한다. 그 밖에서는 실제 전이·공개 DPP의 의미 위반, 잘못된 추적 성공, 또는 SA의 COMPLETE 반환과 완료 술어/차단 유지 구간의 위반이 함께 발생하면 1, 아니면 0이다. 자료 부족의 명시적 실패, 전체 대상을 남긴 INCOMPLETE 및 정확한 NO_LIVE_TARGETS는 공격 성공이 아니다.

**정리 2 (Soundness).** 제2절의 계약과 신뢰 모델 아래

`Pr[Exp_sound(A,λ)=1] ≤ ε_B = ε_X+ε_C+ε_M+ε_H+ε_E`

이다. 각 ε는 감사 이후를 포함한 전체 실행 예산의 상계다.

**증명.** 제4.1절의 전이 보조논증으로 `Pr[Bad]≤ε_B`이고, 그 밖에서는 모든 수락이 실제 생성 값과 현재 상태에 맞는다. 따라서 독립적으로 정의된 제4.2절의 그래프와 typed 소비 대응을 사용할 수 있다. 제4.3절의 경로 귀납은 잘못된 추적 성공을 배제한다. 제4.4절은 정확한 전체 T와 인증된 공통 확인으로 거짓 완료를 배제하며, 현재 상태 검사와 최초 후속 소비에 대한 귀납으로 차단 유지 중 소비도 배제한다. 그러므로 게임에서 1을 출력하는 모든 경우는 같은 Bad에 포함된다. 세 결과를 독립 사건처럼 더해 3ε_B로 계산할 필요가 없다. □

이 정리는 승인된 관계에 대한 건전성이다. 외부 측정값의 진실성, 자동 원인 판정, 영구 차단·기발급 Claim 취소·물리적 회수를 추가로 보장하지 않는다.

## 5. Privacy

### 5.1 분석할 키·암호문과 관측 범위

현행 구성은 하나의 감사키 `PK_B=xG`, `SK_B=x`를 사용한다. 소수 위수 ℓ의 군 `𝔾=⟨G⟩`에서 x는 `𝔽_ℓ*`의 균등 스칼라다. 비밀 분산의 다항식은 `f(0)=x`, 차수 K−1 이하이고 구성원 식별자는 서로 다른 비영 원소다. 각 비밀 조각은 `s_i=f(i)`, 공개 확인 자료는 `V_i=s_iG`다. `N<ℓ`이고 `1≤K≤N`이다. 별도의 키 보호 암호문은 없다.

이벤트 e는 전체 부모 참조와 소비 가능한 출력의 미래 식별자를 순서대로 이은 벡터 `M_e∈𝔽^{d_e}`를 암호화한다. 다음 식은 선택한 DH 구성이며, 상위 분석의 인터페이스와 기밀성 게임은 §5.2에 둔다. 서로 독립인 균등 비영 스칼라 `η_e`로

`R_e=η_eG`, `Z_e=η_ePK_B`, `k_e=H_AuditKey(Z_e)`,

`C_e[j]=M_e[j]+H_AuditMask(k_e,j)`

를 계산한다. 점은 정규 좌표 쌍으로 해시하고 전체 위치 j는 벡터 안에서 중복 없이 인코딩한다. 부모·미래 식별자 저장 배열로 나눌 때에도 j를 다시 0부터 시작하지 않는다. 타입·길이는 공개 관계의 형상으로 정하며 별도 문맥이나 길이 해시를 새로 추가하지 않는다.

공격자는 키 설정 **전에** 조각 노출 집합 I를 고정하며 `|I|<K`다. 관측에는 PK_B, 모든 V_i, 배포·구성원·키 descriptor와 I의 실제 비밀 조각을 포함한다. descriptor 인증은 이 공개 자료와 독립 인증키로 재현 가능한 공개 후처리다. 추가 비밀 의존 정보는 허용하지 않는다. K개 조각, x, η_e, 참여자 비밀·개방값, 키 복원·복호화·보호 관계의 감사/상태 공개 질의는 제공하지 않는다. 공개키로 스스로 암호화하거나 공개 오라클을 질의하는 것은 허용한다.

초기 설정의 비밀 사본 폐기와 외부 조각 전달의 인증·비밀성은 신뢰 경계다. 아래 보조정리는 공개 확인 자료를 관측에 포함하지만, 외부 승인 서비스의 보안·가용성이나 악의적 조각 복구를 증명하지 않는다.

### 5.2 프로토콜이 요구하는 감사 암호화 기밀성

상위 분석은 공개키 암호화의 기밀성을 다음 관측 게임에서 가정한다. 기본 IND-CPA는 같은 길이의 두 평문 사이 암호문 구별 불가능성의 출발점이며, 여기서는 키 조각 노출과 공동 관측을 게임에 명시한다.

1. 공격자가 설정 전에 노출 집합 I를 고정한다(`|I|<K`). 정직 설정으로 만든 PK_B, 모든 V_i, 배포·구성원·키 descriptor와 I의 실제 비밀 조각을 준다. descriptor의 인증은 독립 인증키의 공개 후처리다.
2. 공통 도전 비트 b를 정한다. 공격자가 이전 공개 관측에 따라 최대 m개의 같은 길이 평문 쌍 `(M_e^0,M_e^1)`을 고르면, 독립 정직 난수 r_e로 `AuditEnc(PK_B,M_e^b;r_e)`를 돌려준다. 타입·길이·배열 분할 등 공개 형상은 양쪽에서 같다.
3. 공개키로 직접 암호화하는 계산, 공개 오라클 평가와 로컬 검증은 허용한다. 추가 조각·키 복원·복호화 질의는 없다. 아래 이력 환원은 참여자 비밀·개방값·능동 제출·보호 감사/상태 공개 질의도 제공하지 않는다.

이득은 두 비트 실험에서 1을 출력할 확률의 절댓값 차이다. 환원이 감사키·암호화 난수와 독립적으로 생성한 객체 비밀·개방값, 공동 오라클, 공개 후처리와 증명 시뮬레이터의 평가 질의를 포함한 §5.3의 환경에서 이 성질을 사용한다. 각 감사 벡터 M_e에 대해 같은 평문 공간의 고정 더미 `0^{d_e}`를 택하고, 평문 쌍 `(M_e,0^{d_e})`의 **전체 다중 암호문 치환 이득**을 ε_Aud로 상계한다. 더미의 길이 d_e와 공개 형상은 원래와 같고 암호화에는 정직한 새 난수를 쓴다.

같은 조각 노출·보조정보 조건의 단일 도전 상계가 ε_cpa라면 m개 암호문을 하나씩 바꾸는 hybrid로 `ε_Aud≤mε_cpa`를 쓸 수 있다. 다중 도전 상계로 ε_Aud를 이미 정했다면 m을 다시 곱하지 않는다. 일반 IND-CPA라는 이름만으로 실제 비밀 조각 노출을 포함한다고 추정하지 않는다.

기반 암호화의 IND-CPA 문헌 결과와 적용 조건은 §5.7에 연결한다. 공개 확인 점·정적 노출 조각은 공개키만으로 함께 재현하여 기본 게임의 보조정보로 제공한다. 실제 조각 표본화와 이상적 균등 다항식 설정의 통계적 차이도 ε_Aud에 포함한다. 기반 암호화의 내부 보안 환원은 다시 전개하지 않는다.

### 5.3 원장 전체에 필요한 공동 모형

감사 암호문 외에도 커미트먼트·소비 식별자·거래 증명의 공동 분포를 다룬다. 다음 조건은 기존 수동 관찰 범위를 유지한다.

- 객체 commitment, Voucher resolution secret 및 Note/Voucher 소비 식별자의 다섯 hash domain `H_N,H_V,H_res,H_NF,H_RVNF`를 서로 독립된 고전적 무작위 오라클로 모형화한다. 감사 암호화의 내부 해시와도 분리한다. 선택한 구성의 두 감사 영역 모형은 §5.7에 둔다. 정규 인코딩·domain 분리와 크기 최소 `2^λ`의 균등 출력 영역을 요구한다.
- 객체마다 opening ω를 크기 최소 `2^κ`인 허용 영역에서 독립 균등 생성한다. 소유 비밀도 같은 최소 크기의 정규 유효 영역에서 소유자별 독립 균등 생성한다. κ는 λ에 선형으로 증가한다. 소유 비밀의 정상 재사용은 허용한다. 감사키·다항식 난수·객체 비밀·암호화 난수는 서로 독립이다.
- OwnerKey는 비공개 commitment 내부에만 있다. 별도 공개 OwnerKey나 비밀을 검증할 수 있는 추가 보조정보는 제공하지 않는다. caller·서명키 등 공개 정보는 보호 비밀과 독립이다. 참여자 또는 Voucher 송·수신자가 원래 아는 값을 숨겨 준다는 게임이 아니다.
- **Z: 공동 모형의 다중 정리 ZK.** `SimSetup→(crs,td)`, 모든 정규 x에서 종료하는 total PPT `SimProof(td,x)`가 있다. 참인 이력의 CRS와 전체 증명을 바꾸는 이득은 ε_Z 이하다. 공개 조각 자료·노출 조각·암호문 및 위 오라클을 보조정보로 포함하는 공동 모형과 호환되어야 한다. 실제 해시를 회로에 넣었다는 사실만으로 이 계약이 따라오지 않는다.
- **시뮬레이터의 오라클 접근.** td는 보호 비밀의 정직 생성과 독립적으로 준비하며 생성기의 비공개 해시 질의 기록을 포함하지 않는다. `SimSetup`·`SimProof`와 공개 후처리는 위 일곱 감사·객체/식별자 영역에 자신이 고른 입력을 평가하는 질의로만 접근하고, 내부 표 열람이나 응답 재프로그래밍을 하지 않는다. 증명계 전용 영역의 시뮬레이션은 별도 계약으로 둔다. 이 평가 질의를 모두 Q_A·Q_id의 각 해당 예산에 포함한다. 따라서 시뮬레이터의 비공개 td를 안다는 이유만으로 숨은 입력을 알 수 있는 것은 아니다.

### 5.4 의미적 이력 구별 게임

공격자는 키 설정 전 노출 집합 I를 고르고, 정상 공개 설정·키·모든 V_i·CRS와 I의 조각을 받은 뒤 두 다항 길이 의미적 이력 h_0,h_1을 고른다. 이력은 소유자 이름, 비공개 회계 값, 부모 연결, 이벤트 순서·정책을 지정하지만 감사키·소유 비밀·개방값·암호화/증명 난수는 지정하지 않는다. 각 이력에는 독립 정직 난수로, 우연한 충돌을 제외하면 유효하게 실현하는 명시적 다항 시간 생성기가 있어야 한다. 비밀 난수나 해시 비트에 따라 선택적으로 수락·재표본화하는 이력은 허용하지 않는다. 이는 정상 회계 관계의 유효성을 묻는 조건이며 단순한 증인 존재성보다 강하다.

공개 누출 L이 같은지 검사하고 고정 비트 b의 이력을 실현한다. 허용되지 않는 이력 쌍은 b와 무관하게 거부한다. 관측자는 전체 공개 설정, transactions, commitments, roots, nf/rvnf, producer/spent index, Claims, 모든 암호문과 증명의 바이트를 본다. 공개 RO 질의와 검증 알고리즘의 로컬 실행은 허용하지만 추가 위원회 조각·참여자 비밀·개방값·키 복원·복호화·능동 거래 제출·보호 관계의 감사/상태 공개 질의는 없다.

L의 동일성은 암호문·커미트먼트의 원시 바이트 동일성이 아니라 다음 공개 의미의 동일성이다.

1. 종류·정책·scope, 정확한 입출력 타입/수/순서·sibling 관계, caller/time/deadline, membership root의 prefix 위치, 벡터 길이·저장 배열 분할.
2. 공개 객체와 소비 식별자의 각각의 opaque typed label, 공개 producer/index 구조와 동일성·재사용 패턴. 비공개 생성 참조→미래 spend ID 대응은 L에서 자동 연결하지 않는다.
3. 공개 Claim의 문서 해시·정책·nonce 의미, DPP 공개 세 필드와 외부 공개 정보. 공개 문서 후보나 nonce로 가능한 사전 대입 추론은 숨기지 않는다.

참조·식별자 충돌로 유효 생성이 실패하는 예외는 아래 Bad_id에 포함하며 동일한 실패 기호로 처리한다. 그 확률의 이력 간 차이는 ε_id에 포함한다. 감사·상태 공개를 허용하는 확장은 공개된 식별자의 동일성, 알려진 객체 대응과 참여자의 기존 지식을 L에 추가해 따로 증명해야 한다.

### 5.5 정리와 증명

**정리 3 (Privacy).** 위 게임과 충분조건 아래

`Adv_hist ≤ 2(ε_Z + ε_Aud + ε_id)`

이며 ε_Aud는 §5.2의 실제 평문→고정 더미 평문 암호문 치환의 전체 이득 상계다. m은 같은 공개 형상의 이벤트 수에 대한 상계다. 객체 수 n, 소유자 수 u, 관련 외부·시뮬레이터 객체 오라클 질의 수 Q_id에 대해

`ε_id=O((n+u+Q_id)^2/2^min(κ,λ))`

의 보수적 상계를 쓸 수 있다. 감사 암호화의 구별 비용은 ε_Aud, 객체·식별자 오라클의 추측·충돌은 ε_id로 나눠 기록한다. 구체 구현의 보안 비트·시간 측정값이 아니다.

**증명.** 각 b의 실제 이력을 같은 마지막 분포로 바꾼다.

1. 참인 실제 statement의 CRS와 전체 거래 proof를 ZK 시뮬레이터로 바꾼다. 차이는 ε_Z다. 이후 공개 statement가 바뀌면 같은 td의 `SimProof`를 효율적인 후처리로 실행한다.
2. 제5.2절 게임에서 실제 감사 벡터와 같은 길이 영 벡터를 평문 쌍으로 제출하여 전체 암호문을 고정 더미 평문 암호문으로 바꾼다. 차이는 ε_Aud다. 실제 부모·미래 식별자 평문과 해당 이벤트의 비밀 개방값은 정직 이력 생성기가 알고 있어 환원에 사용할 수 있다. 도전 η·감사키 x를 모르는 환원도 시뮬레이터로 proof를 만들 수 있다. 전체 위치·두 배열 분할·공개 형상은 보존하고, 암호문 바이트는 선택한 방식의 정직 암호화 분포를 따른다.
3. 객체 commitment와 미래 소비 식별자에 독립 균등 typed label을 배정하되 공개 재사용·동일성은 유지한다. Note commitment의 숨은 입력에는 ω가, nullifier 입력 `(cm,s)`에는 소유 비밀 s가 필요하다. 같은 s를 재사용해도 서로 다른 cm는 서로 다른 오라클 입력이다. Voucher commitment와 `H_res(ω)`는 ω를 공유하지만 독립 영역에 속한다. 해결 비밀 z는 별도 균등 값이고 `(rv,z)`에서 미래 식별자를 얻는다. 외부 질의가 ω·s·z를 처음 맞히기 전에는 이 공동 lazy-sampled table과 독립 label을 같은 분포로 결합한다.

마지막 변경의 Bad_id는 비밀을 받지 않은 외부 질의·공개 후처리·증명 시뮬레이터가 숨은 입력의 비밀 부분을 처음 맞히거나 관련 비밀·출력 충돌이 생기는 사건이다. 생성기의 비공개 정직 해시 평가는 추측 질의로 세지 않는다. 더미 암호문은 객체 비밀·개방값과 독립인 설정·난수로 생성되며 감사 암호화의 내부 질의는 객체 오라클의 숨은 입력을 포함하지 않는다. 따라서 Bad_id 전의 관측과 독립 표지를 기존 공동 표 분석대로 결합할 수 있다. 균등 비밀 추측·합집합·생일 충돌 상계가 ε_id다. Voucher의 공유 opening도 공동 표에서 다루므로 개별 은닉성들을 근거 없이 합성하지 않는다.

공개 루트·색인·Claim와 저장 배열은 L과 공개 label의 동일한 함수로 계산한다. Bad_id 밖의 마지막 분포는 같은 L, 같은 키·조각 설정 분포, 독립 난수로 생성한 고정 더미 평문 암호문·typed label과 공개 후처리로만 정해진다. 두 이력의 숨은 회계 값이나 부모·미래 대응은 더 이상 관측에 들어가지 않는다. 양쪽 이력의 세 변경에 삼각 부등식을 적용하면 정리 3이 따른다. □

**거짓 중간 statement.** 더미 암호문이나 label로 바꾼 statement가 원래 관계를 만족한다고 주장하지 않는다. ZK는 최초의 참인 이력에서만 적용한다. 이후의 환원은 스스로 생성한 td로 total PPT `SimProof`를 공개 입력의 후처리로 실행한다. 중간 transcript를 실제 원장에 제출해 수락시키거나 증인 추출을 요구하지 않는다. 이 때문에 수동 게임의 결과를 능동 거래 게임으로 확대하지 않는다.

### 5.6 이 정리에서 따라오지 않는 것

- 공개 V_i가 있는 설정은 정보 이론적으로 감사키를 감춘다고 주장하지 않는다. 상위 증명은 §5.2의 감사 기밀성과 공동 객체 RO/ZK 모형에 의존하고, 선택한 DH 구성의 기밀성 근거는 §5.7에 둔다. K개 조각 또는 원본 키의 사본을 가진 주체에게는 적용하지 않는다.
- K개 조각으로 x를 복원하면 같은 키 영역의 과거·미래 암호문을 로컬에서 읽을 수 있다. 시작점·snapshot·승인 취소가 이미 확보한 키의 능력을 제한하지 않는다.
- 소유 비밀 공개로 Note 소비 대응을 대입하거나, Voucher opening을 아는 송·수신자가 해결 식별자를 계산하는 것을 막지 않는다. 별도 공개 OwnerKey, 부패 참여자의 전체 지식, 적응적 공개와 능동 복호화·거래 질의는 별도 게임이다.
- 실제 해시가 독립 RO처럼 동작하는지, 선택한 군·증명계·스칼라와 인코딩이 위 계약을 만족하는지는 이 이상적 증명으로 확인되지 않는다. 공개 조각 확인 자료의 재현과 특정 해시·회로의 구체 보안 검증을 구분한다.
- 악의적 초기 설정·비밀 사본 보유·무단 조각 전달·악의적 감사자·외부 승인 서비스·암호문 인증에 대한 보안은 새로 증명하지 않는다.


### 5.7 프로토콜 관측 게임과의 연결

이는 공유 점에서 대칭키를 유도하는 hybrid ElGamal의 형태다. 대칭암호 부분은 `E_s(k,M)[j]=M[j]+H_AuditMask(k,j)`로 대응한다. [Boneh–Shoup v0.5 §11.5, Remark 11.1, Theorem 11.5](https://crypto.stanford.edu/~dabo/cryptobook/BonehShoup_0_5.pdf)는 공유 점만 해시하는 변형과 hybrid ElGamal의 선택 평문 기밀성 근거를 제공한다. 기반 암호화의 기밀성은 이 결과를 인용한다.

적용 profile은 문헌 정리의 군·키 유도·대칭암호 전제를 만족해야 한다. 이 분석에서는 `H_AuditKey`와 `H_AuditMask`를 서로 독립된 고전적 무작위 오라클로 두고, 출력 영역은 최소 `2^λ`, 위치 인코딩은 단사로 둔다. 대칭 부분에 요구하는 것은 새로 유도한 키로 한 벡터를 암호화하는 일회용 기밀성이다. 정직 이벤트는 매번 독립 난수를 사용한다. 문헌과 허용 스칼라 영역이 다르면 그 조건화 차이도 적용한 기본 게임의 비용에 포함한다. Jubjub·Poseidon2 구현은 이 추상 profile의 구체 선택이며, 문헌 인용을 그 구현 자체에 대한 동일한 정리로 간주하지 않는다.


**이상적 조각 설정.** x는 기본 공개키 게임과 같은 비영 균등 스칼라이고, 나머지 K−1개 다항식 계수는 `𝔽_ℓ`에서 독립 균등이다. 이 이상적 설정에서 기본 IND-CPA 환원은 x를 몰라도 공개 확인 점과 노출 조각을 함께 생성할 수 있다.

공격자가 설정 전에 고정한 I를 포함하는 K−1개 구성원 집합 J를 고르고, 각 `y_j`를 `𝔽_ℓ`에서 독립 균등으로 뽑는다. K=1이면 J는 비어 있다. 평가점 `{0}∪J`의 Lagrange 기저를 `L_0,L_j`라 두면

`f(t)=L_0(t)x+Σ_{j∈J}L_j(t)y_j`.

따라서 기본 게임에서 받은 공개키 PK_B만으로

`V_i=L_0(i)PK_B+Σ_{j∈J}L_j(i)y_jG`

를 계산하고, I의 비밀 조각으로 알고 있는 y_i를 제공한다. 고정 x에 대해 K−1개 평가값과 K−1개 계수 사이가 가역 선형변환이므로, 이 공개 자료와 노출 조각은 이상적 균등 다항식 설정과 정확히 같은 공동 분포다. descriptor도 독립 인증키의 공개 후처리로 생성한다.

환원은 관찰자가 선택한 평문 쌍을 기본 IND-CPA 도전 질의에 그대로 전달하고 반환된 암호문을 관찰자에게 준다. 나머지 공개 계산과 허용된 독립 보조정보·시뮬레이터 후처리는 같은 공동 모형에서 실행한다. x나 도전 난수를 알아야 하는 연산은 없다. 따라서 이상적 조각 설정의 관측 게임을 구별하는 이득은 동일한 실행 예산의 기본 다중 암호문 IND-CPA 이득으로 상계된다. 일반 IND-CPA에 비밀 조각 노출이 자동 포함된다고 두는 대신, 이 재현으로 연결한다.

**실제 조각 표본화.** 실제 설정과 위 이상적 설정의 전체 공동 분포의 통계적 거리를 δ_set이라 한다. 이상적 표본 전체에서 비영 계수·조각만 허용하도록 영값을 거부하는 설정이라면 합집합 상계 `δ_set≤(K−1+N)/ℓ`를 쓸 수 있다. 이상적 profile에서는 0이다. 이 항은 해당 거부 표본화의 차이이며 임의의 편향된 생성기를 허용하는 근거는 아니다.

동일한 허용 키·정직 난수 profile의 기본 다중 암호문 비용을 `ε_PKE,m`이라 두면

`ε_Aud ≤ ε_PKE,m + 2δ_set`.

두 비트 실험을 각각 실제 설정에서 이상적 설정으로 바꾸는 차이가 δ_set 이하여서 계수 2가 붙는다. 기본 암호화 비용은 문헌 결과를 적용하고, 여기서는 프로토콜이 추가한 조각 설정의 연결 비용만 기록한다. 이 비용을 ε_Aud에 포함한 뒤에는 원장 정리에서 다시 더하지 않는다.

## 6. 증명의 적용과 남은 의무

- X와 Z는 전체 수락 이력의 추출과 공동 관측의 증명 치환을 위한 명시적 조건이다. 기반 지식 건전성과 영지식 구성의 문헌 근거는 원고 B.2·B.3의 사용 위치에, 연구용 SRS·회로별 키·기본 호출·해시는 VI.1에 연결했다. 현재 조건부 분석의 보완을 PLONK 자체나 라이브러리 전체의 보안 재입증 의무로 확대하지 않는다.
- 실제 hash·commitment·OwnerKey·secret/opening domain·암호화 방식·문맥과 난수 검사가 이 문서의 계약을 만족하는지 대응표가 필요하다. 추상 정리와 구체 방식의 검증은 다른 단계다.
- 외부 키 복구·전달과 초기 비밀 사본 관리, 신뢰 기관과 인증된 원장 조회는 명시한 신뢰 경계다. 이에 대한 새 불신 모델 증명을 주장하지 않는다.
- 기존 `model_check.py`의 334개 비교는 해당 모델과 자체 독립 그래프 계산의 일치다. 두 계산은 record 시작을 통상 event reachability로 처리하므로 제4.2절의 규범상 seed projection 전체를 검증하지 않는다. 특히 `Entry e→a`의 record 시작에서 위 차이를 확인할 수 있다. 기존 수치·프로그램은 보존하며 규범 알고리즘 적합성의 근거로 확대하지 않는다.
- 질량 0 출력에 탄소 잔여를 주던 이전 참조 회계 사례는 현행 관계에서 거부한다. 현실 증빙의 진실성과 제품별 배분 기준의 적절성은 여전히 Soundness에서 따라오지 않는다. Soundness는 승인된 관계의 준수를 증명한다.

## 7. 출처와 재현 기록

위 세 정리와 보조논증은 이 v2 구성을 대상으로 작성한 논증이다. 다항식 보간은 [Shamir (1979) §2](https://people.cs.pitt.edu/~litman/courses/cs2001/lectures/lecture-02-p612-shamir.pdf), 기본 IND-CPA와 hybrid ElGamal의 문헌 결과는 [Boneh–Shoup v0.5 §11.3.2 (Theorem 11.1), §11.5 (Remark 11.1, Theorem 11.5)](https://crypto.stanford.edu/~dabo/cryptobook/BonehShoup_0_5.pdf)를 참고했다. 공개 조각 확인 자료와 정적 노출 조각을 기본 IND-CPA 게임에 연결하는 논증은 이 문서의 구성에 대해 작성했다. 특정 암호의 정리를 v2 전체 결과로 이전하지 않는다. 표준 게임·hybrid 방법의 출처, 독립 분석·반례·최종 검토, 이전 상세 판본과 빌드 기록은 [이전 작업 폴더](../outputs/zkdpp-v2-formal-security-2026-09-12)에 보존한다. 출처의 정리를 v2의 증명으로 옮겨 적거나 과거 모델 시험을 암호학적 증명으로 해석하지 않는다.

단일키 Privacy의 2026-09-30 개정·자체 점검·빌드 기록은 [개정 작업 폴더](../outputs/zkdpp-one-key-privacy-2026-09-30)에 있다. 후속 [재점검](../outputs/zkdpp-one-key-privacy-double-check-2026-09-30/review.md)에서 설정 오차의 양 끝점과 시뮬레이터 접근 계약을 보완했다. 이 개정에 대한 독립 검토는 아직 수행하지 않았다. 세 성질로 통합한 이전 판본의 변경 대응표·독립 리뷰·빌드 기록은 [통합 작업 폴더](../outputs/zkdpp-v2-three-property-security-2026-09-12)에 보존한다. 기존 보장의 귀속을 정리한 것으로 실제 배포의 가정 충족이나 더 넓은 프라이버시를 새로 입증한 것은 아니다.
